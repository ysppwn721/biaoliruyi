## 1. 项目基础信息

### 项目定位

知链是一个**本地运行的跨文档结论验证与增量修复原型**。用户导入一份 Excel 事实表和一份或多份 Word/PPT 成果文件，系统从成果中识别受支持的数值论断，人工确认论断与事实 ID 的来源关系；事实数值变化后重新验证论断，预览受影响内容，人工批准后只修复失效论断并重新读取 Office 文件复核，最后导出真实的 Office 文件与核验记录。

### 核心能力

- 确定性规则识别四类文字论断（数值、增长率、定性方向、排名、阈值）+ 单系列簇状柱形图。
- Decimal 精确计算 + 显式单位换算 + 统计口径校验，不做 `eval`、不让模型算数。
- 双人工闸门闭环：**来源确认** 与 **修复批准** 分离，均可分批、可关窗稍后继续（持久化待办）。
- 版本化事务：每次变更走「复制目录 → 写新版本 → 重读复核 → 原子换指针」，复核失败自动废弃新版本。
- 可选 DeepSeek 官方 API 来源关联建议（仅建议，不确认、不写文件）。
- 证据链验证智能体（确定性状态机编排，非 ReAct）。
- 只读 MCP stdio 服务（供 Claude Desktop / Cursor 等调用，7 个工具）。

### 版本

当前版本 `0.2.0`（`zhilian/__init__.py` 中 `__version__`）。

### 输入 / 输出

| | 内容 |
| --- | --- |
| 输入 | 1 份 `.xlsx` 事实表 + ≥1 份 `.docx`/`.pptx`；≤10 个文件、合计 ≤30MB |
| 输出 | 更新后的 Word/PPT、核验记录 JSON、核验报告 Markdown、ZIP 成果包 |

- 144 项自动化回归测试全通过（2026-09-24 复核）。

### 系统边界 / 不是什么

- **不是**通用文档理解器：只处理受支持的数值论断，因果解释、主观判断、任意自然语言不在计算验证范围。
- **不是**全格式 Office 编辑器：不承诺任意排版保真，页眉页脚/备注/母版/复杂对象等不在首版范围。
- **不是**自由工具 ReAct 智能体：Agent 是确定性状态机，大模型只做来源关联建议，不计算、不裁决、不写文件。
- **不是**多租户/后台调度服务：单进程本地 JSON 存储、共享工作空间、无角色权限。

## 3. 环境与启动方式

### 依赖、Python 版本、虚拟环境

- Python **3.11 及以上**（本机验证环境为 Windows + Python 3.12）。
- 虚拟环境已建在项目根目录 `.venv`，依赖已安装。
- `requirements.txt`：运行时依赖（fastapi / uvicorn / python-multipart / openpyxl / python-docx / python-pptx / httpx / mcp）。
- `requirements-dev.txt`：在运行时基础上加 `pytest`。
- `requirements-lock.txt`：本机验证过的完整依赖版本（Windows + Python 3.12）；跨平台部署需重新验证安装与导出。

### 启动命令、端口、健康检查

```powershell

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 启动（三选一）
.\start.bat                    # 双击 / 命令行
.\start.ps1
.\.venv\Scripts\python.exe run.py
```

默认地址 **http://127.0.0.1:8765**（`run.py` 从 `ZHILIAN_HOST` / `ZHILIAN_PORT` 读取，默认 127.0.0.1:8765）。**以启动日志和健康检查为准**，不要为换端口改前端代码（前端用相对 `/api/...`）。

健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8765/api/health
```

健康响应应含 `status: ok`、`version: 0.2.0`。注意 `model.enabled=true` / `key_configured=true` 只说明服务端读到了密钥，**不代表真实 API 已连通**；必须成功请求一次建议才能确认连通性。

复制 `.env.example` 为 `.env` 后编辑（`.env` 已被 `.gitignore` 排除，绝不提交）：

- **禁止多进程/多 worker 共享同一个数据目录**：`Store` 只有进程内锁 + 本地 JSON/文件版本，多进程并发写会破坏一致性。
- 公网部署必须 HTTPS 反向代理，不直接公开明文 Basic Auth 端口；API 文档与下载受同一密码保护。
- 所有用户共享一个工作空间，不适合未经隔离的公开匿名服务。
- 不要把真实 API Key 写进聊天、前端、源码或文档。

## 4. 业务操作流程

### 用户从新建项目到导出完整流程

1. **新建项目**：上传 1 份 `.xlsx` + ≥1 份 `.docx`/`.pptx`（可多选、提交前可移除单个文件）。
2. **确认来源关联**：审阅论断与事实 ID 的候选 `refs`，逐项确认或批量确认后处理歧义项；只有 `confirmed=true` 的论断才允许修复。
3. **改数据**：可直接改数值，或用「导入更新后的 Excel」上传保存后的新表（网页不监听磁盘、不会自动改写已下载/打开的文件）。
4. **更新数据并验证**：系统重算论断，标出「仍成立 / 已失效 / 无法判断」。
5. **预览修复**：查看失效论断修改前后对照，勾选批准。
6. **下载成果包**：含源表、修改后的文件、`知链核验记录.json`、`核验报告.md`、完整 JSON 记录。
7. **撤销**：恢复上一次数据变更或修复之前的版本。

### 文件上传约束、必填字段、大小行数限制

- 每批 1 份 `.xlsx` + 至少 1 份 `.docx`/`.pptx`，最多 10 份、合计 30MB。
- 单文件展开后 ≤5000 个 ZIP 条目且 ≤80MB；拒绝宏文件、扩展名与内容不符的文件。
- Excel 首行必须含以下列（顺序可变）：`事实ID、主体、指标、期间、数值、单位、统计口径`。
- 事实 ID 必须唯一、非空、≤80 字符；主体/指标/期间/单位/统计口径不得为空。
- **公式单元格会被拒绝**（请先重算并保存为已核实数值）。
- 每张事实表 ≤2000 行、≤100 列；单个项目 ≤2000 条事实。

### 更新数据规则、预览-确认-修复-导出逻辑

- 更新入口要求**事实 ID 集合 + 主体/指标/期间/单位/统计口径保持不变**，只能改数值或调整行顺序；增删事实或改变含义必须重建项目并重新确认关联。
- 一次只上传一个更新 Excel；不要把两个不同版本同时作为一批上传。
- 差异预览**不会写入项目版本**；确认后才建立新源表 generation 并重新验证。
- 修复只接受「已确认且当前为失效」的论断；预览/批准均不写入版本，批准后才写新 generation。

### 撤销、导出功能说明，哪些操作是禁止的

- **撤销只有单步**：只恢复上一次文件变更（数据导入或修复）之前的状态，不可连续多步、不可重做。
- 导出下载前会再次做 SHA 校验。
- **禁止**：未确认关联的项目上调用修复；同时上传两个更新 Excel；直接编辑 `.zhilian/<wid>/state.json` 或 generation 文件来「修数据」；多进程写同一数据目录。

## 5. 接口与核心机制

### 关键 API 与核心参数

所有项目接口的 `{wid}` 是 **32 位小写十六进制项目 ID**；写接口必须带当前 `revision`，不匹配会返回「项目已在其他窗口更新，请刷新后重试」（乐观锁）。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查与模型配置状态 |
| GET | `/api/projects` | 列出本地项目 |
| POST | `/api/projects/demo` | 创建演示项目 |
| GET | `/api/template` | 下载事实表模板 |
| POST | `/api/projects` | multipart 创建项目（字段 `name`、重复 `files`） |
| GET | `/api/projects/{wid}` | 获取项目、论断、事实、检查状态、未覆盖文本 |
| POST | `/api/projects/{wid}/links` | `{revision, links:[{claim_id, refs}]}` 确认来源 |
| POST | `/api/projects/{wid}/facts` | `{revision, values:{fact_id:number}}` 直接改数值 |
| POST | `/api/projects/{wid}/source/preview` | multipart `revision`+`file`，预览外部 Excel |
| POST | `/api/projects/{wid}/source` | multipart `revision`+`file`，正式导入外部 Excel |
| POST | `/api/projects/{wid}/repair` | `{revision, claim_ids}` 修复选中失效论断 |
| POST | `/api/projects/{wid}/undo` | `{revision}` 撤销上一次文件变更 |
| POST | `/api/projects/{wid}/suggest` | `{revision}` 请求可选模型关联建议 |
| POST | `/api/projects/{wid}/agent/run` | `{revision}` 运行智能体 |
| POST | `/api/projects/{wid}/agent/decide` | `{revision, decisions:[...]}` 提交人工决定 |
| GET | `/api/projects/{wid}/agent/status` | 只读：phase/pending/trace/result/stale |
| GET | `/api/projects/{wid}/files/{fid}` | 下载单个当前文件 |
| GET | `/api/projects/{wid}/export` | 下载成果与核验记录 ZIP |

安全：设置密码后 Basic Auth 用户名固定 `zhilian`；非 GET/HEAD/OPTIONS 跨站 Origin 被拒绝；响应带 no-store/nosniff/same-origin/DENY 等头。

### 版本/快照机制、事务、SHA 校验

- 项目目录结构：`.zhilian/<wid>/state.json` + `v0/` + 多个 `v<随机hex>/`（含当前代文件与 `previous-state.json`）。
- `state.json` 关键字段：`revision`（每次确认关联/数据变更/导入/修复/建议/撤销递增）、`generation`、`documents`（含 SHA256）、`facts`、`blocks`、`claims`、`history`、`audit`、`last_repair`、`agent`。
- 写操作先 `copytree` 旧 generation → 写新 generation → 重新扫描验证 → 通过才替换当前状态；失败 `rmtree` 废弃新目录。
- `verify()` 在写操作前比较 revision 与所有文档 SHA256，防止并发窗口或磁盘文件被外部改动后静默覆盖。

### 修复逻辑：自动改 vs 人工复核

**自动修复（经人工批准后）**：
1. 只接受 `confirmed` 且 `inconsistent` 的论断；
2. 按 location 分组、按字符范围逆序替换（避免前面替换改变后面锚点）；
3. Word run 级补丁尽量保留未修改 run 格式；PPT 普通文本同理，单系列柱形图重建数据系列；
4. 重新读取生成的 Office 文件；
5. 验证选中论断已一致、其他支持范围内 block 文本未变化；失败废弃新版本。

**只做人工复核（不自动改）**：来源关联的确认、OCR 图片文字、歧义来源消歧、因果解释、口径冲突、零/负基期、无法唯一匹配——这些返回「无法判断」或进入人工待办，不会自动写入。

## 6. 能力边界

### 系统支持识别、自动处理的场景

- 数值引用：`本期销售额为125万元`。
- 增长率：`较上期增长25%`、下降、持平；定性方向 `较上期增长`（方向仍成立时保留原句）。
- 排名：`A产品销量最高`、`并列最高`（只对已确认的比较集合负责）。
- 阈值：`超过120万元`、`低于100万元`、`未超过预算`。
- Word 普通正文 + 一层普通表格；PPT 普通文本框、表格、单系列簇状柱形图。
- 单位换算（如 1.25 亿元）、复合句逐项拆分。

### 不支持、只能人工复核的场景

- 因果解释（`增长主要来自渠道优化`）、主观意见、背景说明、句中连接词。
- 图片中的文字（OCR 只读、不可修复）、页眉页脚、备注、母版、组合对象、复杂域、复杂图表（多系列等）、宏。
- 旧格式 `.xls/.doc/.ppt`（需另存为新格式）。
- 隐式的财年/同比基期/累计范围推断、多主体同指标图表自动匹配。
- `unmatched_segments`（未覆盖原文片段）不能解释为「错误数量」，也不能因同段另一条通过而默认为正确。

## 9. 已知问题、坑点、禁止操作

### 容易踩的坑

- 端口以启动日志和 `/api/health` 为准；前端用相对 `/api/...`，不要为换端口改前端。
- 模型建议只是「来源关联建议」，不自动确认、不自动改文件；必须成功请求一次才代表连通。
- `engine.check` 的错误分类依赖错误文案字符串精确匹配（P2-1）：改文案会让分类静默退化为 `needs_review`，改文案时务必同步排查。
- 智能体诊断阶段逐条全量写盘（P2-2）：数百论断项目会拖慢并放大磁盘写入。
- 版本目录与导出 ZIP 永不清理（P2-3）：长期使用磁盘无限增长，且**目前没有删除/重命名项目入口**。
- 撤销单步、不可重做（P2-4）。
- 页眉多段落时漏发「未纳入检查」警告（P1-1）。
- 后端支持图片直传，前端上传入口未暴露（P1-2）。
- 长任务（OCR/模型最长 60 秒）无进度且不可取消。
- 更名「表里如一」尚未执行：用户可见处（web 标题/页脚、导出包文件名、报告标题、demo 文案、`app.py` title、MCP 服务名、README/文档）仍是「知链/ZHILIAN/zhilian」，若决赛启用新名须全量替换并重新导出。

### 绝对不能做的事

- **手动改 `.zhilian/<wid>/state.json` 或 generation 文件「修数据」**：会破坏 SHA256 与版本一致性。
- **多进程/多 worker 写同一数据目录**。
- 在未确认关联的项目上调用修复。
- 把 API Key 写进前端、源码、聊天或文档。
- 把原型当通用系统对外承诺（全格式兼容、任意文档理解、多租户）。

### 部分限制是设计而非 bug

- 只修复「已确认且失效」的论断；未识别文本不算通过。
- 更新入口要求事实 ID 集合与语义保持不变，这是为避免沿用错误关联，不是缺陷。
- 单步撤销、无多租户/角色权限、无自动版本清理，是当前原型的既定设计。
- OCR 论断只读、不可修复、不计入 repairable，是既定支线。
