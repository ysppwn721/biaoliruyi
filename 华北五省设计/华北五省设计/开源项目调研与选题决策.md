# 开源项目调研与选题决策

> ## 定稿（2026-09-13）：主选 = 校园政策与办事流程智能体
>
> 原第 2 名升为**备选**并暂停推进。原因：团队缺少外部资源，就业中心无法提供真实投递/录用数据，人岗匹配方向失去唯一的差异化来源。
>
> 本文档第一、三、五节（校园政策的开源组合、复用合规清单）**继续有效并作为开工依据**；第二节（求职方向仓库）**仅作调研存档，不要投入开发**。
>
> 重点提醒：既然主选落地政策方向，交付物中只保留 **MIT / Apache-2.0** 依赖（LangGraph、RAGFlow、Reactive-Resume），其余自定义许可项目仅作设计参考、不进代码库。理由见 `新版决策文档评审.md` 第三节。

## 结论先行

我们不需要寻找完全同款项目。凡是在 RAG、文档解析、智能体工作流、流程管理、简历处理、岗位匹配、证据引用等方面相似的热门仓库，都可以用来借鉴或作为底座。

综合 GitHub 项目成熟度、可复用程度、第一次参赛的实现难度、差异化空间和比赛要求，建议：

> **主选：校园政策与办事流程智能体**  
> **备选：可验证的人岗匹配与求职教练智能体**

## 一、校园政策与办事流程方向

### 1. Dify

[langgenius/dify](https://github.com/langgenius/dify)

可借鉴：知识库、RAG、Agent、工作流、模型接入、API、日志和 Web 应用发布。

推荐用法：作为快速原型和模型服务底座；我们自己开发政策版本管理、条款引用、流程状态机和材料闭环。

注意：Dify 不是简单 MIT 许可证，使用前必须核对当前版本 License 和附加条件。

### 2. RAGFlow

[infiniflow/ragflow](https://github.com/infiniflow/ragflow)

可借鉴：PDF/Word/网页解析、文档切分、知识库、检索和引用。

推荐用法：处理学校通知、办事指南和规章制度等复杂资料。

### 3. MaxKB

[1Panel-dev/MaxKB](https://github.com/1Panel-dev/MaxKB)

可借鉴：中文知识库问答、本地部署、多模型接入、工作流和组织知识库产品结构。

推荐用法：作为中文场景和国产模型友好的 RAG 底座备选。

### 4. FastGPT

[labring/FastGPT](https://github.com/labring/FastGPT)

可借鉴：中文 RAG、知识库、工作流、引用展示和多模型配置。

### 5. LangGraph

[langchain-ai/langgraph](https://github.com/langchain-ai/langgraph)

可借鉴：多智能体状态、条件分支、人工审核、重试和失败恢复。

推荐用法：把政策问答实现为真正的办理流程智能体。

### 6. Flowise

[FlowiseAI/Flowise](https://github.com/FlowiseAI/Flowise)

可借鉴：可视化 Agent、RAG 和工具调用。适合快速原型，但正式作品的关键机制不能完全依赖默认流程。

### 7. Open WebUI / Chatbot UI

[open-webui/open-webui](https://github.com/open-webui/open-webui)  
[mckaywrigley/chatbot-ui](https://github.com/mckaywrigley/chatbot-ui)

可借鉴：对话界面、文件上传、多模型切换、用户权限和前端组件组织。它们更适合做交互参考，不是校园业务底座。

### 校园方向必须自己完成的部分

- 政策文件版本和生效期管理；
- 条款级原文引用；
- 新旧政策冲突检测；
- 身份—事项—材料匹配规则；
- 办理流程状态机；
- 材料缺项检查和进度追踪；
- 人工确认、审计日志和本校真实案例。

## 二、求职与人岗匹配方向

### 1. JobSync

[Gsync/jobsync](https://github.com/Gsync/jobsync)

GitHub 公开信息显示，该项目约有 1000+ stars，使用 MIT License，近期仍有提交。功能包括 AI 简历审查、岗位匹配、求职申请跟踪、任务管理、自托管和 Ollama/MCP 相关能力。

可借鉴：岗位、简历、申请记录的数据模型，以及完整求职流程。

不能直接照搬。我们必须增加程序化匹配、证据锚点、反编造约束和可量化评测。

### 2. Reactive Resume

[AmruthPillai/Reactive-Resume](https://github.com/AmruthPillai/Reactive-Resume)

可借鉴：简历编辑器、多版本、模板、PDF 导出和前端交互。

适合作为简历编辑和导出层，再接入我们自己的人岗匹配智能体。

### 3. OpenResume

[xitanggg/open-resume](https://github.com/xitanggg/open-resume)

可借鉴：简历创建、模板、字段组织和 PDF 输出。

### 4. Magic-Resume

[Magic-Resume/Magic-Resume](https://github.com/Magic-Resume/Magic-Resume)

可借鉴：AI 简历优化、ATS 分析、岗位匹配、职业指导和面试准备。

使用前要检查当前代码是否完整可运行、License、模型依赖和第三方服务绑定情况。

### 5. Job Pilot

[adrianhajdin/job_pilot](https://github.com/adrianhajdin/job_pilot)

可借鉴：Agentic workflow、岗位跟踪、求职任务管理和前后端工程结构。项目较新，建议作为参考实现而不是唯一核心依赖。

### 求职方向必须自己完成的部分

- 岗位学历、专业、技能、年限和证书等硬条件结构化；
- 程序化计算匹配分；
- 岗位原文和简历原文双向证据锚点；
- 禁止生成用户不存在的经历、证书和项目；
- 建议采纳率、证据覆盖率和匹配一致性评测；
- 面向中国高校毕业生的规则与交互。

## 三、两个方向的开源复用组合

### 校园政策方向

- RAGFlow、MaxKB 或 FastGPT：文档解析和知识库；
- Dify 或 LangGraph：智能体和工作流；
- PostgreSQL/SQLite：政策版本、条款和流程状态；
- 自研：流程状态机、引用校验、冲突检测和材料闭环。

### 求职方向

- JobSync：求职管理和申请跟踪参考；
- Reactive Resume 或 OpenResume：简历编辑和 PDF 导出；
- Dify/LangGraph：岗位分析、面试和反馈工作流；
- 自研：程序化匹配、证据锚点、反编造和评测。

## 四、最终优先级

### 第一名：校园政策与办事流程智能体

理由：

- 底层技术可以大量复用；
- 本校资料和真实用户较容易获得；
- 规则、材料和流程天然可验证；
- 现成的完整同款项目较少；
- 自主创新空间大；
- 更适合第一次参赛团队在有限时间内完成公网系统、文档和演示。

建议题目：**“校园政策智办：基于证据链和流程状态机的办事智能体”**。

### 第二名：可验证的人岗匹配与求职教练智能体

理由：

- 成熟开源项目较多，开发速度快；
- 用户和测试数据容易获取；
- 现场演示非常直观；
- 适合实现岗位分析、面试和反馈闭环。

主要问题：同质化项目多。不能只做 AI 简历生成，必须突出“岗位硬条件程序化匹配 + 双向证据锚点 + 禁止编造经历”。

建议题目：**“职证匹配：证据约束下的人岗匹配与求职反馈智能体”**。

## 五、开源复用合规清单

每个使用的仓库都要记录：

- 仓库名称和 URL；
- commit、release 或版本号；
- License；
- 复用的模块；
- 是否修改以及修改内容；
- 是否保留版权和许可证声明；
- 哪些代码是第三方，哪些代码是团队原创；
- AI 生成代码占比；
- 是否需要公开修改后的源代码。

通知允许 AI 辅助编程和设计，但要求说明模型名称、版本号和 AI 编写代码比例。开源项目可以复用，场景设计、业务规则、智能体流程、评测方法和创新机制必须由团队自己完成并能在答辩中解释。

## 六、最终行动方案

先用 48 小时分别制作校园政策和求职匹配的最小原型，比较资料获取、真实用户反馈、公网运行、结果验证和现场演示效果。若没有额外行业资源，正式选择校园政策方向；若已有就业指导老师、招聘数据或成熟简历前端，则可把求职方向提升为主选。

无论选择哪个方向，最小可行版本都应包含：一个具体用户、一个真实案例、两个智能体、三个工具、一套可重复评测、公网部署、测试账号、设计文档、源代码和演示视频。
