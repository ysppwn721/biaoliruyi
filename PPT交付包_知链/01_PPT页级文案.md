# 知链答辩 PPT 页级文案

## 第1页｜标题

**标题：** 知链：跨文档证据链智能体

**副标题：** Excel 数据变化驱动 Word/PPT 结论验证、增量修复与可审计导出

**页脚：** 团队项目｜版本 0.2.1

**画面：** 使用架构图局部或 Excel → Word/PPT 的简洁流程图。

## 第2页｜问题与场景

**核心句：** 数据表更新后，报告中的数字、增长率、排名和阈值判断容易失效，人工逐段查找、计算、修改、复核成本高。

**三类痛点：**

- 数据在 Excel，结论分散在 Word/PPT，来源关系不清晰。
- 数值变化可能只影响局部论断，整篇重写会引入新的错误。
- 修改后需要证明“改对了、没有误改、可以追溯”。

**画面：** 左侧 Excel，右侧 Word/PPT，中间用红色断裂链路表示来源失联。

## 第3页｜产品目标与边界

**核心句：** 知链把“发现失效 → 找到依据 → 请求确认 → 局部修复 → 重新验证”变成可审计流程。

**输入：** Excel 事实表、Word/PPT 成果文件。

**输出：** 新版本 Word/PPT、变更报告、来源证据、审计记录。

**边界：** 支持受约束的数值、增长率、定性方向、阈值、排名和部分图表；不承诺任意自然语言因果解释、图片文字识别后的自动改写或复杂 Office 排版全兼容。

## 第4页｜智能体在项目中的具体作用

**标题：** 智能体是证据链流程编排器

**流程：** 准备 → 关联 → 诊断 → 询问（人工）→ 修复 → 复核 → 完成。

**智能体负责：** 调用解析、候选关联、诊断、修复、复核工具，保存运行 ID、待办、决定和轨迹，支持中断恢复与幂等执行。

**模型负责：** 对已识别且未确认的论断提出事实来源候选，或润色诊断解释。

**确定性引擎负责：** Decimal 计算、单位和口径约束、增长率/阈值/排名判断、文件写入前后的校验。

**人工负责：** 最终确认来源和批准修复。

**画面：** 使用 `知链智能体架构图.svg`。

## 第5页｜系统技术架构

**模块：**

- `app.py`：HTTP API、上传、认证、项目入口。
- `engine.py`：论断识别、确定性计算和验证。
- `office.py`：Word/PPT 锚点定位、文本和图表修改。
- `store.py`：版本、快照、撤销、导出、审计。
- `agent.py`：状态机式智能体和人工闸门。
- `llm.py` / `reranker.py`：可选远程 API 和本地候选排序。
- `mcp_server.py`：只读 MCP 工具，为外部 Agent 提供解析、验证和诊断能力。

**关键设计：** 模型不计算、不裁决、不直接写文件；所有修复必须经人工批准并重新读取验证。

## 第6页｜一次完整业务流程

**演示步骤：**

1. 上传 Excel、长文 Word 和 PPT。
2. 系统抽取事实、论断、文件位置和候选来源。
3. 智能体展示来源建议，用户确认或处理歧义。
4. Excel 更新后，系统只标记受影响论断。
5. 用户预览修复前后差异并批准。
6. 导出新版 Office 文件和变更报告。
7. 重新读取文件，确认修复项通过且其他支持范围内容未被误改。

**画面：** 使用 6 个编号卡片，配一张修复前后 Word 截图或 `长文Word修复结果对比.svg`。

## 第7页｜长文 Word 压力测试

**标题：** 长文本场景下保持局部修复

**已验证数据：** 24 章、约 1.7 万字、280 条论断候选。

**场景 A：** 销售额 125→123，80 项需要修复，200 项仍成立。

**场景 B：** 销售额 125→90、A 产品 80→60、支出 80→110，232 项需要修复，48 项仍成立。

**结果：** 两种场景导出后均重新读取并恢复到 280 项一致。

**口径：** 这是本地长文测试夹具结果，用于证明实现行为，不代表外部行业泛化。

**画面：** 使用 `长文Word修复结果对比.svg`。

## 第8页｜评测集与方法

**数据分层：**

- seed/sanity：30 个文档组、180 个决策点；普通 120、歧义 30、对抗 30；dev/test 按文档组隔离。
- 长文夹具：25 个文档组、280 个决策点；dev 231、test 49；标签来自已知夹具和确定性引擎重放。

**指标：** Top-1 来源准确率、错误关联率、歧义拒答率、误拒率、提示注入劫持率、延迟和候选数量。

**方法要求：** 同一评测集比较规则、link_rules、本地 reranker、API 和融合方案；测试集冻结后再报告。

## 第9页｜真实评测数字

**API 在长文夹具上的结果：**

- 整体 Top-1：86.8%（280 条）。
- test 留出组 Top-1：71.4%（49 条）。
- 整体错误关联率：1.07%；test 错误关联率：4.08%。
- 25 次调用全部成功；平均批次延迟约 2.69 秒，P95 约 4.02 秒。

**seed/sanity API 结果：** Top-1 60.0%，错误关联率 33.3%，歧义拒答率 0，对抗劫持率 0。

**本地 reranker 安全基线：** seed 集 Top-1 40.0%，错误关联率 0，歧义拒答率 100%，误拒率 60%。它当前适合作为保守的候选筛选/拒答模块，不能宣称准确率优于 API。

**link_rules 回放：** 当前实现只给规则候选增加“已记住”偏好，不自动替换来源；seed 180 条中命中 30 条，长文夹具 280 条中命中 53 条。它提升审阅效率，不构成独立模型准确率。

**脚注：** 长文夹具不是外部行业泛化数据；规则回放 100% 只说明标签重放一致。

**画面：** 使用 `答辩评测指标对比.svg`，并在图旁放数据集口径说明。

## 第10页｜性能与本地部署

**事实表解析：** 1999 条事实读取中位耗时约 0.118 秒，规模曲线保持近似线性。

**候选预算：** seed 集平均 1.67 个候选、P95 为 3；长文夹具平均 1 个候选、P95 为 2。说明 reranker 不需要对全量事实做成百上千次前向。

**模型包：** bge-reranker-v2-m3 ONNX INT8 权重约 570MB，独立于基础源码包，可选安装。

**CUDA 结论：** CUDAExecutionProvider 可用，但当前 INT8 图因 MemCopy/算子回退，实测 CPU 平均约 363ms，CUDA 平均约 636ms；默认采用 CPU，CUDA 保留为实验后端。

**画面：** 使用 `事实表读取性能曲线.svg`，旁边放“基础包 / 本地模型包 / API 模式”三档部署卡片。

## 第11页｜创新点与优势

**创新点：**

- 把 Excel、Word、PPT 之间的来源关系显式化为证据链。
- 将模型限制在语义候选，计算和文件修改由确定性程序完成。
- 来源确认和修复批准双闸门，支持版本、SHA256、审计和撤销。
- Agent 具备状态、待办、恢复、幂等和 MCP 只读扩展接口。

**相对普通文档问答工具的优势：** 可验证、可回滚、可追溯；结果直接落到真实 Office 文件。

## 第12页｜下一阶段与答辩收束

**近期工程路线：**

1. 完成 `link_rules`、纯规则、本地 reranker、API、融合方案的统一对比。
2. 两名成员独立标注真实难负样本和歧义样本，冻结 dev/test。
3. 根据阈值扫描确定“自动建议 / API 兜底 / 人工确认”的分流策略。
4. 再评估是否用 LoRA/QLoRA 微调小型 cross-encoder；不从零训练大模型。
5. 补充 OCR、多模态、更多 Office 复杂对象和客户端适配。

**收束句：** 知链的核心价值不是让模型替人做最终决定，而是让跨文档数据变化变成有证据、有闸门、可复核的自动化流程。
