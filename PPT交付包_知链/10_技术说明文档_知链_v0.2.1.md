# 知链 v0.2.1 技术说明文档

## 1. 项目定位

知链是一个跨文档结论验证与增量修复系统。用户提供一份 Excel 事实表和一批 Word/PPT 成果文件，系统建立“论断—事实—文件位置”的证据链。当 Excel 数据发生变化时，知链只重新验证受影响的论断，生成诊断、修复预览和变更报告，用户确认后才写入新的 Office 文件版本。

系统的核心目标是让修改过程可解释、可回滚、可复核。它不承诺理解任意自然语言，也不允许模型直接计算或直接改文件。

## 2. 输入、输出与支持范围

输入包括：

- `.xlsx` / `.xlsm` 事实表（当前建议使用已保存的数值，不接受依赖缓存的公式结果）。
- `.docx` Word 文档。
- `.pptx` PowerPoint 文档。
- 可选图片/OCR支线和只读 MCP 调用。

输出包括：

- 新版本 Word/PPT 成果文件。
- Excel 差异和受影响论断列表。
- 诊断结果、来源证据和人工决定。
- 变更报告、审计记录和完整 JSON 导出包。

当前确定性引擎支持数值、增长率、定性方向、阈值、排名和部分单系列图表。页眉页脚、备注、母版、图片内文字、复杂域、宏、复杂图表和旧式 `.doc/.xls/.ppt` 不属于首版稳定支持范围。

## 3. 总体架构

```text
浏览器 / MCP 客户端
        │
        ▼
FastAPI app.py ── 上传、认证、限流、项目接口
        │
        ▼
Agent agent.py ── 状态、待办、恢复、人工决定、执行轨迹
        │
   ┌────┼───────────┬────────────┐
   ▼    ▼           ▼            ▼
office  engine      store        llm/reranker
解析锚点 规则识别    版本快照      可选语义候选
写入文件 Decimal计算 审计/导出     API/本地模型
```

主要模块：

| 模块 | 职责 |
|---|---|
| `zhilian/app.py` | HTTP 接口、上传限制、Basic Auth、CSRF 和静态页面 |
| `zhilian/agent.py` | 证据链智能体状态机、人工闸门、待办恢复和轨迹 |
| `zhilian/engine.py` | 论断抽取、单位归一化、Decimal 计算和确定性裁决 |
| `zhilian/office.py` | Excel/Word/PPT 解析、位置锚点、文本和图表修改 |
| `zhilian/store.py` | 项目版本、快照、SHA256、撤销、导出和审计 |
| `zhilian/llm.py` | DeepSeek 关联建议和诊断解释校验 |
| `zhilian/reranker.py` | 可选 BGE ONNX INT8 本地候选排序 |
| `zhilian/mcp_server.py` | 面向外部 Agent 的只读解析、验证和诊断工具 |
| `web/` | 不依赖前端构建工具的中文工作台 |

## 4. 智能体流程

智能体不是自由生成式聊天机器人，而是带状态和人工闸门的流程编排器：

```text
prepare → link → diagnose → ask → decide → repair → verify → done
```

1. `prepare` 检查文件版本、哈希和原文锚点。
2. `link` 合并规则候选、已记忆候选、本地 reranker 和可选 API 建议。
3. `diagnose` 执行数值、增长率、阈值、排名和图表检查。
4. `ask` 生成待人工确认的来源或歧义清单。
5. `decide` 保存用户对来源和修复的分批批准。
6. `repair` 在新版本快照中执行最小范围修改。
7. `verify` 重新读取输出文件，确认选中论断通过且支持范围内的其他内容没有被误改。
8. `done` 导出成果包和审计记录。

来源确认和修复批准是两个独立闸门。关闭窗口、刷新网页或重启服务后，可以根据 `state.json` 中的待办继续；旧版本或外部文件变化会使待办失效并要求重新运行。

## 5. 模型路由与安全边界

生产路由为：

```text
规则唯一确定       → 直接进入人工确认
规则多候选         → link_rules / 本地 BGE 排序
规则零候选或低置信 → 本地 BGE 语义召回
BGE 低置信         → DeepSeek API 兜底或转人工
最终来源           → 用户确认
计算、裁决、写文件  → 确定性程序
```

本地模型采用 `bge-reranker-v2-m3` ONNX INT8，可选独立安装，约 570MB，不进入基础安装包。模型不可用时自动退回规则/API流程。BERT 微调模型在内部相似数据上出现过拟合，因此保留为研究对照，不作为线上默认模型。

模型仅接收论断文本和事实元数据（主体、指标、期间、单位、统计口径），不会接收完整 Office 文件或事实表全部数值。API 建议必须通过事实 ID 校验，且不会绕过人工确认。

## 6. 评测结果与解释

### 6.1 语义改写四档对比

72 条中文语义改写论断中，规则唯一确定 15 条，规则零候选 57 条。gold 由固定事实表程序化生成，属于评测数据，不是真实行业人工真值。

| 配置 | Top-1 | 错误关联率 | 覆盖率 | 拒答率 |
|---|---:|---:|---:|---:|
| 纯规则 | 19.44% | 1.39% | 20.83% | 79.17% |
| 单独本地 BGE | 87.50% | 12.50% | 100.00% | 0.00% |
| 规则 + 本地 BGE | 87.50% | 12.50% | 100.00% | 0.00% |
| 规则 + 本地 BGE + API | **93.06%** | **4.17%** | **97.22%** | 2.78% |

Top-1 表示首选事实与 gold 一致的比例；错误关联率表示已经给出来源但来源错误的比例；拒答率表示系统没有给出来源、转人工确认的比例。生产上错误关联比拒答更危险，所以 API 允许少量安全拒答来降低错误来源。

### 6.2 长文与外部语料

- 长文 Word 夹具：24 章、约 1.7 万字、280 条论断，数据变化场景下已完成局部修复和重新验证。
- 公开年报外部集：36 份 PDF、576 条程序化标签，仅用于压力验证，不能称为人工行业准确率。
- 全量回归：当前根目录 `pytest` 为 **250 passed**，有 1 个依赖弃用警告。

规则回放的 100% 只说明封闭夹具的确定性重放一致，不能外推真实行业泛化准确率。

## 7. Office 修改与版本安全

每个项目和文件版本都有 revision 与 SHA256。修复流程在新快照中执行，失败时不覆盖旧版本。修复后重新读取 Word/PPT，检查：

- 选中论断是否通过；
- 文本、表格或受支持图表是否写入预期值；
- 未选中的支持范围内容是否保持一致；
- 审计记录是否包含来源、差异、决定和时间。

用户下载的是新成果文件，外部原始文件不会被直接覆盖。Excel 更新要求事实 ID 集合、主体、指标、期间、单位和口径保持一致；新增事实或改变含义应建立新项目。

## 8. 安装与部署

当前提供两种 Windows 形态：

1. **标准安装版**：`Zhilian-0.2.1-windows-x64-setup.exe`。支持选择安装位置、开始菜单、可选桌面快捷方式和卸载；默认安装到当前用户 `%LOCALAPPDATA%\Programs\Zhilian`。
2. **免安装版**：`Zhilian-0.2.1-windows-x64.zip`。解压后运行 `Zhilian\启动知链.bat`。

用户项目数据默认写入 `%LOCALAPPDATA%\Zhilian`，卸载程序不会删除项目数据。macOS/Linux 通过 GitHub Actions 或目标系统执行 `packaging/build.sh` 构建；Linux 另提供用户目录安装脚本和 Docker 路线。本机已完成 Windows 构建与健康检查，macOS/Linux 仍需目标系统端到端验收。

公网部署必须使用 HTTPS 反向代理、访问密码、调用配额和上传限制。DeepSeek Key 只能放服务端环境变量，不得写入源码、PPT、安装包、截图或日志。

## 9. 已知限制与后续路线

已知限制：单进程 JSON 存储不适合多租户并发；复杂 PDF 表格、图片文字、复杂 Office 对象不保证自动修复；当前模型评测样本仍需要更多真实人工标注。

后续优先级：

1. 完成 20 页以上 PPT 和一份 Excel 对几十/上百份 Word 的压力测试。
2. 在真实行业文档上补充去重、难负样本和人工 gold，重新校准 BGE/API 阈值。
3. 增加批处理队列、失败重试、进度展示和结果清单。
4. 增加 PDF 表格结构化、OCR 和多模态支线，并继续沿用人工确认闸门。
