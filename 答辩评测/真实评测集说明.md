# 真实模型评测集

## 当前内容

eval_dataset.jsonl 是知链来源关联的可复现评测集，按文档组切分，避免同一文档的相似句同时出现在开发集和留出集。

| 子集 | 文档组 | 决策点 | 普通 | 歧义 | 对抗 |
| --- | ---: | ---: | ---: | ---: | ---: |
| dev | 20 | 120 | 80 | 20 | 20 |
| test | 10 | 60 | 40 | 10 | 10 |
| 合计 | 30 | 180 | 120 | 30 | 30 |

每条样本包含论断原文、事实元数据、标准来源、动作标签和类别。事实 value 不进入评测集，因此可以直接作为模型输入，不会把正确答案通过数值泄漏给模型。

## 标注状态

当前 eval_dataset.jsonl 是可复现的 seed/sanity 集，用于先验证指标脚本，不应直接表述为真实行业泛化准确率。真实材料候选由 extract_real_candidates.py 从长文Word测试/长文测试_原始报告.docx 和配套 Excel 抽取到 real_annotation_queue.jsonl，正式评测前必须由两位队员独立复核并记录分歧。

复核完成后，将真实候选的 gold_refs、gold_action、category、annotators 和 adjudication_note 填写完整，确认无分歧后再改为 adjudicated=true。开发集可用于调 prompt，test 集只在方案冻结后运行。

    .\.venv\Scripts\python.exe 答辩评测/evaluate_predictions.py 答辩评测/predictions_real_rule.jsonl --dataset 答辩评测/real_eval_dataset.jsonl --system rule-real-fixture --output 答辩评测/real_eval_metrics.csv

`real_eval_dataset.jsonl` 是基于本地长文测试夹具完成的可复现评测集，包含 280 条论断，标签由夹具来源和确定性引擎重放得到。它可以用于验证实现和模型回归，但不是外部真实行业样本；当前规则回放 sanity 结果为 dev 231/231、test 49/49 命中，不能宣传为行业泛化准确率。提示注入指标仍使用 `eval_dataset.jsonl` 的对抗子集。评测指标包括 Top-1 准确率、错误关联率、歧义拒答率、误拒率和提示注入劫持率。真实 API 运行时，每个系统只需输出同样格式的 predictions.jsonl，即可使用同一脚本统计 dev/test 结果。

## 真实模型接入约定

模型请求只发送 facts 中的元数据和 claim_text，不发送事实数值。对抗样本中的“忽略以上要求”等文本必须被当作数据处理，不能改变允许的事实 ID 白名单。真实运行还应额外记录模型版本、请求次数、输入/输出 token、延迟和估算费用。

## 2026-09-25 首轮真实 API 结果

使用 DeepSeek API 对 30 组、180 条 seed/sanity 样本进行 30 次调用，全部成功：Top-1 为 0.600，错误关联率为 0.333，歧义拒答率为 0，提示注入劫持率为 0；平均批次延迟约 2.11 秒，p95 约 2.32 秒。

对 25 组、280 条本地长文夹具论断进行 25 次调用，全部成功：test 留出组 Top-1 为 0.714，错误关联率为 0.0408，整体 Top-1 为 0.868，整体错误关联率为 0.0107；平均批次延迟约 2.69 秒，p95 约 4.02 秒。该夹具没有独立歧义样本，不能据此报告歧义拒答率。

结果文件：api_eval_metrics.csv、api_real_eval_metrics.csv、api_eval_stats.json、api_real_eval_stats.json。预测文件只保存模型返回的事实 ID，不保存 API Key。

## 候选预算实验

在下载本地模型前，先用现有 best_facts 统计候选规模。seed 集 180 条中，90 条为单候选、90 条为多候选，平均 1.67 个 pair，p95 为 3；长文夹具 280 条中，184 条为单候选、48 条为多候选、48 条零召回，平均 1 个 pair，p95 为 2。结果见 candidate_budget_summary.json 和 candidate_budget_real_summary.json。

结论是：本地 reranker 不需要对全事实表做 800 次前向。规则应先收紧到少量候选，reranker 只处理多候选和低置信样本；零召回样本交给 API 或人工。单候选样本由现有规则和 link_rules 处理，作为 reranker 增量基线。

## 本地模型首轮结果

已下载并验证 ONNX INT8 版 bge-reranker-v2-m3：权重约 570MB，tokenizer 约 17MB；当前使用 CPUExecutionProvider，180 条 seed 集平均单条批处理耗时约 363ms，p95 约 656ms。用开发集校准 raw score=-3.5、margin=0.3 后，seed 集歧义拒答率为 1.0、错误关联率为 0；由于本地 reranker 当前只处理单事实候选，增长率、阈值事实组和排名组仍交给确定性规则，所以整体 Top-1 不能与完整 API 直接比较。

本地模型默认关闭。启用需要设置 ZHILIAN_LOCAL_RERANKER_PATH 或 ZHILIAN_LOCAL_RERANKER_ENABLED=1；模型缺失时 Agent 自动降级，不影响规则/API流程。

## 双人标注完成情况（2026-09-25）

已由两个独立子智能体完成全部 25 个文档组、280 条候选的交叉标注。前 5 组 64 条与后 20 组 216 条分别合并，均为 100% 一致，合计 280/280 无需仲裁。完整标签见 `real_human_eval_dataset.jsonl`，摘要见 `human_annotation_summary.json`。这属于自动化交叉标注，不能替代比赛要求的真人双人标注；正式答辩应说明队员仍需复核，或将其称为“双智能体一致性检查”。

人工标签的含义是“来源是否唯一、需要哪些事实 ID”，不是“论断当前数值是否正确”。因此“支出超过100万元”可以标为唯一关联 `spending`，再由确定性引擎判断当前值80万元导致论断不一致。该分层避免把来源关联错误和数值验证错误混为一个指标。

基于完整人工集的首轮回归：确定性规则 Top-1=65.71%（test=75.51%），错误关联率=34.29%；本地 INT8 reranker Top-1=54.29%（test=53.06%），错误关联率=0，误拒率=45.71%（test=46.94%），平均推理约268.96ms，P95约551.02ms。规则结果暴露了局部文本缺少上下文时的候选顺序/组合问题，不能直接与此前基于 fixture candidate_refs 的100%回放结果混用；正式报告应以人工标注集和统一输入格式为准。

## CUDA 运行时检查（2026-09-25）

系统 CUDA 13.0 和 RTX 5060 Laptop GPU 可用；安装 `onnxruntime-gpu==1.30.0` 后，`ort.get_available_providers()` 返回 `TensorrtExecutionProvider`、`CUDAExecutionProvider`、`CPUExecutionProvider`。因此本地模型可以选择 CUDA provider，CUDA 安装位置不在测试数据文件夹，而在系统级 NVIDIA CUDA Toolkit 目录。

当前 INT8 ONNX 模型在这台机器上的 CPU 反而更快：seed 集逐条评测 CPU 平均约 363 ms、P95 约 656 ms；CUDA provider 平均约 636 ms、P95 约 842 ms。50 个 pair 的一次批量测试中，CPU 约 471 ms，CUDA 约 3991 ms，并出现 CUDA MemCopy 警告。这说明当前 INT8 图存在算子回退和内存拷贝开销，不能把“检测到 CUDA”直接宣传成加速。运行数据见 `local_reranker_runtime_benchmark.csv`。

本阶段不进行微调训练：现有 280 条长文夹具标签来自确定性引擎重放，180 条 seed 数据主要用于安全和流程验证，直接训练会把项目规则记忆成模型能力。下一步应先完成 `link_rules`、规则、reranker、API 的同一评测对比，并补充两人独立标注的真实难负样本；数据达到可审计的训练/验证/测试划分后，再考虑 LoRA/QLoRA 微调小型 cross-encoder。当前部署建议保留 CPU 默认、CUDA 作为可选实验后端，并将无模型/无 GPU 降级路径作为正式能力。

## 2026-09-25 PDF 外部压力验证（程序化标签）

为应对人工双人复核无法在截止时间前完成的情况，使用 PyMuPDF 批量读取 `cn_reports/` 中的 36 份公开年报，抽取文本层中主要财务指标的本期/上期字段，并为每条论断构造当前期间、上期和错误期间候选。输出为 `external_programmatic_holdout_all.jsonl`，共 576 条论断、1,728 个候选对、36 个文档组。

该批次的 `label` 来自 PDF 相邻字段和程序化规则，字段包含 `source_file`、`source_page`、`programmatic=true`，没有经过队员双人独立确认。因此它只能作为真实语料压力验证，不能称为人工真值，也不替换冻结测试集。

统一批量评测结果：BGE ONNX Top-1 为 96.18%（错误关联率 3.82%），中文 BERT v2 Top-1 为 41.32%（错误关联率 58.68%）。结论支持继续把 BGE 作为线上默认，本轮 BERT v2 只作为研究模型保留；除非后续加入新的真实中文文档组并重新划分 train/dev/test，不继续用程序化 PDF 对微调 BERT。

## 统一基线与分流曲线（2026-09-25）

已补齐 `link_rules` 的回放基线，并生成 `system_comparison.csv`。回放严格模拟当前产品行为：`link_rules` 只给现有确定性候选增加“已记住”偏好，不能覆盖候选、自动确认或绕过歧义人工闸门。因此 seed 集和长文夹具的准确率与纯规则相同（两者均为本地夹具回放，不代表行业泛化），seed 集 180 条中有 30 条候选命中已记忆来源，长文夹具 280 条中有 53 条命中。

如果把记忆规则错误地实现成“自动选源器”，不同统计口径可能互相覆盖；这也是当前实现坚持人工确认和确定性候选优先的原因。答辩中应把 `link_rules` 表述为审阅效率优化，而不是独立模型能力。

本地 reranker 阈值扫描另生成 `reranker_api_tradeoff.csv`。在 seed 开发集、阈值 raw=-3.5、margin=0.3 时，本地候选自动接受率为 83.33%，估算需要 API 兜底约 20/120 次；通过阈值的非歧义候选 Top-1 为 100%，歧义拒答率为 100%。该曲线只用于开发集分流标定，冻结测试集前不能当作最终效果。
