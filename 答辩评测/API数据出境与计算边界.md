# API 数据出境与计算边界（答辩专章）

更新时间：2026-09-27
用途：回答评委必问的"用 API 会不会导致企业内部数据泄露"与"系统到底谁在算"

---

## 一、先分清两个问题（这是最容易被问倒的地方）

| 问题 | 答案 |
| --- | --- |
| **系统会不会算？** | **会，而且必须算** —— 用 `Decimal` 确定性计算，可复现、可审计 |
| **大模型会不会算？** | **不会** —— 它只输出事实 ID，不参与任何算术 |

**这不是矛盾，而是分工。**

### 观察到的现象：改数字后比例也跟着变 —— 那是设计核心

| 环节 | 实现 | 证据 |
| --- | --- | --- |
| 增长率计算 | `engine.py`：`(after − before) / before × 100`，`Decimal` + `ROUND_HALF_UP`，并把完整算式写进 `calculation` 字段供人核对 | `engine.py` |
| 派生事实重算 | `graph.py`：`sum` / `diff` / `ratio` / `growth` 四则算子，按拓扑序级联 | `graph.py` |
| 影响半径 | `graph.impact()` 给出"改这个数会影响哪几条结论" | `graph.py` |
| 大模型 | prompt 明写"不要计算、修改文字或编造 ID"；输出白名单校验只接受事实 ID | `llm.py` |

**答辩原话**：
> "改一个数、下游比例自动跟着变，这正是我们最想展示的能力——**事实依赖图 + 确定性引擎**。它算的是 `Decimal`，不是神经网络。模型在这一步没有参与，它只被允许回答'这句话说的是哪个指标的哪一期'，连一个加法都不做。这就是我们和纯 AI 方案的分水岭：它们的判定是模型输出，我们的判定是可复现的算式。"

## 二、在线模式实际外发什么（逐字段核对代码，不是承诺）

`zhilian/llm.py` 构造的请求体：

| 内容 | 是否外发 | 说明 |
| --- | --- | --- |
| 事实表**数值 `value`** | ❌ **从不发送** | 只发 `id / subject / metric / period / unit / scope` |
| Excel 原始文件 | ❌ 从不发送 | 只在本机解析 |
| **论断原文 `original`** | ⚠️ **会发送** | 如"本期销售额为125万元"，**原文含数字** |
| 事实 ID / 论断 ID | ⚠️ 会发送 | 本地标识，无业务含义 |
| 表格坐标 `sheet` / `cell` | ⚠️ 会发送 | 仅"AI 解释诊断"功能，会暴露表结构 |
| `expected`（应改成什么） | ⚠️ 会发送 | 计算后的修正文本，含数字 |

**默认端点**：`https://api.deepseek.com/chat/completions`（DeepSeek 官方）

---

## 三、三种模式的外发量

| 模式 | 外发数据 | 适用 |
| --- | --- | --- |
| **无模型** | **零** —— 不联网、无任何外部调用 | 涉密、断网 |
| **离线** | **零** —— 本地 ONNX 模型随包分发，本机推理 | 内网、数据不出域 |
| **在线** | 仅**规则零候选**论断的原文 + 事实元数据 | 表述复杂、追求召回 |

**实测比例**：280 条论断的夹具上，**232 条（83%）由规则直接判定、不出本机**，只有 48 条（17%）会送到 API。

## 四、本轮新增的两个能力（P0 / P1）

### P0 · 端点可配置 —— 让数据真正不出内网

```bash
ZHILIAN_LLM_BASE_URL=http://10.0.0.5:8000/v1   # 指向自建 vLLM / Ollama / 内网网关
```

代码里端点不再硬编码；`/api/health` 会显示 `provider`（"DeepSeek" 或 "自定义端点"）与 `base_url`，运维可一眼核对流量去哪。

**这一条的意义**：信创与涉密环境的硬要求是"数据不出内网"。企业把后端指向自己的私有化大模型后，**在线模式也不再有任何数据出域**——三种模式就都安全了。

### P1 · 发前脱敏 —— 外部端点也拿不到数字

```bash
ZHILIAN_LLM_REDACT_NUMBERS=1
```

开启后，论断原文里的数字被替换为 `［数值］`：

```
本期销售额为125万元        ->  本期销售额为［数值］万元
较上期增长25%             ->  较上期增长［数值］%
3,379.37万元的营业收入增长553.21%  ->  ［数值］万元的营业收入增长［数值］%
```

**技术依据**：模型的任务是"判断这句话在说哪个指标的哪一期"，**数值对它是冗余信息**——prompt 里本来就禁止它计算。所以脱敏不损失它需要的信息。

> ⚠️ **诚实边界（必须同时说）**：**该开关对匹配准确率的影响尚未实测**，因此：
> 1. 默认是**关闭**的（`=0`）；
> 2. 我们不宣称"脱敏零影响"——这需要跑一遍对照评测才能说。

## 五、答辩问答（建议原话）

**问：用 API 会不会泄露企业内部数据？**

> "会，所以我们把它做成了可选项，而且能精确说清发的是什么。
> 在线模式下，**事实表的数值从不外发**——只发主体、指标、期间、单位、口径这些元数据，让模型做语义匹配。发出去的还有论断原文，也就是报告作者自己写出来的那句话。
> 真正敏感的 Excel 源数据不出本机。而且 83% 的论断根本不需要联网，判定在本机完成。
> 如果连原文也不能出内网，两件事：一，改用离线模式，一次请求都不发；二，把后端指向企业自建的模型服务——我们已经支持配置端点，再加一个发前数字脱敏开关。"

**问：那系统到底有没有在计算？**

> "系统一直在算，而且这是核心能力。改一个数，依赖它的增长率、占比、差额会按依赖图自动重算——用 `Decimal`，结果和算式都留在界面里给人核对。
> 不算的是大模型。它的输出只能是一个事实 ID，连加法都不做。"

**问：既然模型不算，为什么还需要它？**

> "因为规则只会词面匹配。同一批语义我们只改措辞测过：把'销售额'写成'销售收入''营收''营业总收入'，规则一条都认不出，Top-1 从 100% 掉到 33%，而本地语义模型是 94%。
> 所以分工是：**规则做词面召回，模型做语义召回，计算和裁决永远由确定性引擎做。**"

## 六、需要避免的说法

| 不要这样说 | 原因 |
| --- | --- |
| 「我们的数据不出本机」 | 在线模式下论断原文会外发；必须限定为"无模型/离线模式"或"事实数值不外发" |
| 「我们不做计算」 | **系统必须做计算**，这正是能力；只能说"模型不做计算" |
| 「脱敏没有精度损失」 | 尚未实测，不能宣称 |
| 「我们的端点比竞品更安全」 | UpSlide 用客户**专属 Azure 实例**，治理更成熟；我们应表述为"支持指向自建服务" |
| 「模型帮我们算出了 25%」 | 算出来的是 `Decimal`；模型只选来源 |

## 七、与竞品的对照（如实）

| | UpSlide | 表里如一 |
| --- | --- | --- |
| 送出的内容 | 官方文档："User Information, prompt" | 论断原文 + 事实元数据（**不含事实数值**） |
| 文档本体 | 留在本地，工具本地执行 | 留在本地 |
| 判定是否必须联网 | **是** | **否**，无模型/离线模式零请求 |
| 端点 | 客户**专属 Azure AI Foundry** | 默认公有端点，**可配置为自建** |
| 计算归属 | 模型判定 | **确定性引擎（Decimal）** |

> **公平说明**：UpSlide 的**专属实例**比我们的公有端点更隔离；我们的优势是**可以完全离线**。两者的取舍不同，不要宣称某一方全面更好。
