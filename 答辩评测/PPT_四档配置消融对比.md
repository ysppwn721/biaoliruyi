# PPT 素材：四档配置消融对比

## 一张图说明四种方案

图：`four_way_ablation_comparison.svg`

数据：同一批 180 个程序化决策点、30 个文档组，离线重放，不调用 API。

| 配置 | Top-1 | 错误关联率 | 歧义拒答率 | 误拒答率 |
|---|---:|---:|---:|---:|
| 纯规则 | 100% | 0% | 100% | 0% |
| 单独本地模型 | 40% | 0% | 100% | 60% |
| 规则 + 本地模型 | 100% | 0% | 100% | 0% |
| 规则 + 本地模型 + API | 100% | 0% | 100% | 0% |

## 答辩解释

原有夹具中 150 条样本由规则唯一确定，30 条是应人工确认的歧义样本；没有真正的“规则零候选”或“规则多候选单事实”样本。因此规则+本地和规则+本地+API与纯规则结果相同，说明模型被安全地限制在困难场景中，且没有破坏规则结果，但不能用这张表声称模型提升了准确率。

模型增量要看独立语义改写集：72 条改写论断上，规则 Top-1 为 19.44%，BGE ONNX 为 87.50%。这两张图要一起展示：第一张证明分层路由的安全性，第二张证明语义模型在规则零候选场景中的召回价值。

全量 API 在同一历史夹具上的 Top-1 为 60%、错误关联率 33.33%、歧义拒答率 0%，说明让 API 接管全部样本会增加错误关联风险。生产策略是规则优先、本地模型处理困难候选、API 只做低置信度兜底，任何建议仍需人工确认。

## 语义改写集真实 API 复测

为验证 API 在真正的规则零候选场景中的作用，又在 72 条中文语义改写集上进行了真实 DeepSeek 调用，共 2 批、72 条论断，调用成功率 100%，平均批次延迟约 4.86 秒。该集合中规则只能唯一确定 15 条，另外 57 条为规则零候选；因此它专门测量自然语言改写下的语义召回能力。

图：`semantic_four_way_ablation_v2.svg`

| 配置 | Top-1 | 错误关联率 | 覆盖率 | 拒答率 |
|---|---:|---:|---:|---:|
| 纯规则 | 19.44% | 1.39% | 20.83% | 79.17% |
| 单独本地 BGE | 87.50% | 12.50% | 100% | 0% |
| 规则 + 本地 BGE | **87.50%** | 12.50% | 100% | 0% |
| 规则 + 本地 BGE + API | **93.06%** | **4.17%** | 97.22% | **2.78%** |

这组结果说明单独本地模型和规则+本地模型在本数据集上确实相同：规则唯一确定时两者都采用规则，规则零候选时都由 BGE 进行语义排序。因此这里不是实现重复，而是路由安全性与语义召回能力的叠加。API 只接管 BGE 低置信结果：Top-1 从 87.50% 提升到 93.06%，错误关联率从 12.50% 降到 4.17%，覆盖率仍保持 97.22%，仅 2 条低置信样本拒答。

答辩时应明确三个指标的含义：Top-1 是最终首选事实与程序化 gold 一致的比例；错误关联率是已经给出来源但来源错误的比例；拒答率是系统没有给出来源、转人工确认的比例。生产上错误关联比拒答更危险，所以 API 允许少量安全拒答来换取错误下降。

限定：语义改写集的 gold 由固定事实表程序化生成，不是真人行业真值；API 建议仍需人工确认，不能直接写回 Office 文件。

## 推荐讲解词

> 我们把系统拆成四种配置做消融。在语义改写集上，纯规则只能命中 20.83% 的样本；单独本地 BGE 和规则+本地都达到 87.50%，说明 BGE 补足了规则零候选的语义召回，但直接全量采用会留下 12.50% 的错误关联。再让 API 只复核 BGE 的低置信结果，Top-1 提升到 93.06%，错误关联率降到 4.17%，并保留 2.78% 的安全拒答。系统的价值在于分工：规则保证确定性，本地模型覆盖同义改写，API 处理少量难例，最终来源仍需人工确认。
