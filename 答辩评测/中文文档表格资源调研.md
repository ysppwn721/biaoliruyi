# 中文「文档 + 表格」资源调研

> 用途：为 reranker 微调补充**中文**训练对（现状：自建中文对 1936 对 + 英文公开数据 129146 对）
> 调研方式：逐个数据源实测可达性与许可证，非二手转述
> 结论：**巨潮资讯网（cninfo）是最优源**，接口已实测可用；HF 上现成的中文表格数据集极少

## 一、结论速览

| 源 | 类型 | 语言 | 规模 | 许可证 | 实测状态 |
| --- | --- | --- | --- | --- | --- |
| **巨潮资讯网 cninfo** | 上市公司年报（文字+报表） | 中文 | 10000+ 份/年 | 公开披露信息 | ✅ 接口可用 |
| **国家统计局** | 统计公报/年鉴（文字+表） | 中文 | 极大 | 政府公开信息 | ✅ 站点可达 |
| **CFQA**（HF） | 中文金融问答 | 中文 | 1000 条 | CC-BY-4.0 | ✅ 文件可列 |
| TAT-QA / FinQA | 英文财报问答 | 英文 | 129146 对 | MIT | ✅ 已下载 |
| 上述 HF 中文表格集 | — | — | — | 401 不可访问 | ❌ 非公开 |

**关键结论：现成的中文「文档+表格」配对数据集在公开渠道几乎不存在**，
必须从**原始公开文档**自行构建。好在最优源是免费的、官方的、接口开放的。

## 二、首选：巨潮资讯网（cninfo.com.cn）

### 为什么它最合适

**证监会指定的上市公司信息披露平台**，年报 PDF 里同时包含：

- **管理层讨论与分析**章节 → 叙述性文字，含大量数值结论
  （「本期营业收入 12.5 亿元，同比增长 25%」「毛利率较上年下降 3.2 个百分点」）
- **财务报表**与**主要会计数据**表格 → 结构化数值

**这两者天然在同一文档中**，正是 TAT-QA / FinQA 的中文对应物，且与知链的任务形态
（文档文字结论 ↔ 数据表事实）完全一致。

### 接口已实测可用（无需登录、无需密钥）

```bash
curl -X POST "http://www.cninfo.com.cn/new/hisAnnouncement/query" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -H "User-Agent: Mozilla/5.0" \
  --data "pageNum=1&pageSize=5&column=szse&tabName=fulltext&category=category_ndbg_szsh&seDate=2024-01-01~2024-12-31"
```

实测返回：

```
totalRecordNum = 11427            ← 2024 年年度报告数量
announcementTitle = *ST宁科2022年年度报告（2024年12月修订）
adjunctUrl = finalpage/2024-12-28/1222168015.PDF
```

- `category_ndbg_szsh` = 年度报告（深市）；沪市用 `category_ndbg_sse`
- PDF 下载地址：`http://static.cninfo.com.cn/{adjunctUrl}`
- 支持按关键词 `searchkey` 检索（例如检索含「营业收入」的公告）

### 许可与合规

| 项 | 说明 |
| --- | --- |
| 性质 | 上市公司**法定公开披露**信息，公开可查 |
| 用于研究/训练 | 属合理使用范畴，但**需保留来源与日期** |
| **再分发** | ⚠️ **不要把原始 PDF 或全文入库/进交付包** |
| 建议做法 | 只落库**派生出的训练对 + 溯源信息**（沿用现有 `public_dataset_manifest.json` 的 policy） |

**沿用你现有的原则**：`training-only; do not include raw public data in delivery package`。

### 需要的处理链路（工作量评估）

| 步骤 | 工具 | 难度 |
| --- | --- | --- |
| 1. 检索 + 下载年报 PDF | cninfo 接口 + `requests` | 低（接口已验证） |
| 2. PDF 抽文字与表格 | `pdfplumber` / `camelot` / `PyMuPDF` | **中**（表格抽取是难点） |
| 3. 识别数值结论句 | 现有 `zhilian/engine.py` 规则 | 低（已有） |
| 4. 表格转事实元数据 | 需写转换器（主体/指标/期间/口径） | **中** |
| 5. 生成正负训练对 | 沿用 `build_reranker_training_pairs.py` 思路 | 低（已有） |

**关键难点在第 2 步**：中文年报 PDF 的表格结构比 TAT-QA 的规整 JSON 复杂得多
（合并单元格、跨页表、无表头）。建议先做 **20—30 份试跑**验证可行性，再决定是否规模化。

## 三、次选：国家统计局（stats.gov.cn）

| 优点 | 说明 |
| --- | --- |
| 完全免费、官方、无版权争议 | 政府信息公开 |
| **统计公报**：文字叙述 + 配套数据表 | 结构规整，比年报 PDF 好抽 |
| **统计年鉴**：纯表格，结构极规整 | 可作事实表来源 |

实测：`https://www.stats.gov.cn/` → HTTP 200；`https://data.stats.gov.cn/` → HTTP 200

**适合场景**：构造"宏观数据类"训练对，表格规整度高于年报。
**局限**：叙述文字与表格多为**分开的两个文件**（公报文字 + 年鉴表），
需要人工或规则建立对应关系，不像年报那样同文档。

## 六、建议方案（按性价比排序）

### 方案 A（推荐）：先用现有中文对，不扩张

**理由**：`reranker_training_pairs.jsonl` 的 1936 对审计全部通过
（跨 split 泄漏 0、字段缺失 0、正负冲突 0、与任务同分布）。

**行动**：直接开始微调，先拿到"微调 vs 零样本"的对比数字。
**成本**：0 天数据工作，只需装 PyTorch。

### 方案 B：cninfo 年报抽样构建中文对（若 A 的数字不够）

**行动**：
1. 用已验证的接口下载 **20—30 份**年报
2. 验证 PDF 表格抽取可行性（**这是成败关键，先做小样本**）
3. 走通"文字结论 → 事实表 → 正负对"链路
4. 若可行再扩大到 100—200 份，预期可产出 **3000—8000 对**

**成本**：2—4 天（主要在 PDF 表格抽取）
**登记**：在 `public_dataset_manifest.json` 增加条目，注明 cninfo 来源与"仅派生数据入库"

### 方案 C：统计局数据构造宏观类训练对

**适合**：想增加**领域多样性**（防止模型只认"销售额/成本"这类词）。
**成本**：1—2 天，表格规整、抽取较易。

## 七、风险提示

1. **PDF 表格抽取是最不确定的环节**。中文年报常见合并单元格、跨页表、无表头续表，
   抽取质量直接决定训练对质量。**务必先做 20—30 份的小样本验证**。
2. **不要把原始 PDF 或全文入库**。沿用现有 policy，只提交派生数据 + 溯源信息。
3. **时间成本**：校赛临近，方案 B 的 2—4 天可能挤占其他工作。
   若方案 A 的数字已经能支撑答辩，**不必做 B**。
4. **最终评测集必须是中文且人工确认**。公开数据只能进训练集，
   不能用来报告"泛化准确率"——这条与现有 `真实评测集说明.md` 的口径保持一致。
