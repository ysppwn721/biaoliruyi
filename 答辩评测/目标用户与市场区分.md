# 目标用户与市场区分（PPT 素材）

> 用途：答辩 PPT「用户定位」与「竞品区分」章节的素材
> 原则：只写**可验证的事实**，不做无法自证的量级承诺

## 一、竞品现状：数据一致性治理已有商业方案

报告数字与源数据不一致，不是没人做过。市面已有成熟产品，且都已用上 AI：

| 产品 | 定位 | 形态 | 用户 |
| --- | --- | --- | --- |
| **UpSlide** | 财务与报告团队的质量保证 | Microsoft Office 插件 | 企业金融/报告团队，按用户订阅 |
| **CCH Tagetik Intelligent Disclosure** | 企业披露管理 | 企业级平台 | 上市公司财务与合规部门 |
| **WPS 365** | 表格跨表联动 | 金山生态内公式联动 | 个人/企业，但**仅限表格之间** |

**它们的共同特征**：

- 都面向**企业**，需企业采购、IT 部署与运维
- 都**依赖 Microsoft Office 或自建生态**
- 一致性判定多为**云端 AI 黑盒**

> UpSlide 有 AI Consistency Check，CCH Tagetik 提供 AI 驱动的披露文档校验。
> 这说明：**"用 AI 检查报告数字"已不是空白，不能宣称首创。**

## 二、我们的区分：三条架构事实，不是定位口号

| 维度 | 企业级产品 | 表里如一 | 性质 |
| --- | --- | --- | --- |
| **运行依赖** | 必须安装 Microsoft Office | **直接读写 OOXML，不装 Office 也能运行** | ✅ 架构事实 |
| **数据流向** | 云端 SaaS，数据上传 | **全程本地，数据不出本机** | ✅ 架构事实 |
| **费用** | 企业订阅（按用户） | **免费** | ✅ 事实 |
| **成本结构** | 需 IT 采购与运维 | **单机运行，无需 IT 资源** | ✅ 事实 |
| **判定方式** | AI 黑盒判定 | **确定性计算（Decimal + 单位/口径约束）** | ✅ 可复现 |
| **能力边界** | 指出"可能不一致" | **最小改动修复 + 重新读取文件复核** | ✅ 可验证 |

**关键差异是最后两行**：

- 企业产品的 AI 校验只能给出"这里可能不一致"；**审计场景需要的是可追溯的证据**，而不是模型判断
- 企业产品**发现问题即止**；表里如一会**按字符锚点做最小改动，并重新读取生成的文件独立复核**

## 三、目标用户：三段式

### 核心用户（主推）

**学生、科研人员、高校与科研团队**

**为什么最匹配**——他们天然产出**文档三件套**：

| 材料 | 作用 | 与本系统的关系 |
| --- | --- | --- |
| **Word 报告** | 实验报告、论文、结题报告、成果报告 | 正文含数值结论 → **被核验对象** |
| **Excel 数据表** | 原始数据、统计结果 | **事实来源** |
| **PPT** | 开题、中期、答辩、汇报 | 含结论与图表 → **被核验对象** |

**典型痛点**：

- 数据复核后，报告与幻灯片里的数字要**逐篇手动改**，容易漏
- 「本期销售额较上期增长 25%」这类结论，**数据一变就要重算**
- 答辩稿与论文数据**互相不一致**，自己看不出来

### 扩展用户

**中小企业中需要对外提交材料的人**

- 项目申报、政府汇报、投标文件、年度总结
- 特点：有 Word 报告 + Excel 数据，但没有企业 IT 资源，也不会为核对数字买企业级订阅

### 未来方向（需要新增能力，暂不计入现有范围）

**纯表格场景（如小微商户的进销存对账）**

- 需求真实存在：多张表之间核对、月度与总账比对
- **但形态不同**：这类场景是「表 vs 表」对账，**没有含数值结论的 Word 正文**
- 本系统的核心能力（从 Word/PPT 正文定位数值论断）在此场景**用不上**
- 若要覆盖，需新增「表格对账」入口——底层已有 `engine` 的确定性计算与 `graph` 的依赖图，但**尚无对应产品入口**

> **答辩建议**：把这一条放在"未来规划"，不要当成现有能力讲。
> 若被问"能否用于小卖店"，如实回答："需要新增表格对账入口，当前版本聚焦含叙述文字的文档。"

## 四、可量化的优势（用现有实测数据）

| 指标 | 直接调用 API | 分层协同（规则 + 本地模型 + API 兜底） |
| --- | --- | --- |
| 事实关联 Top-1 | 0.868 | **1.000** |
| 错误关联率 | 0.011 | **0.000** |
| API 调用量 | **280 次 / 280 条** | **48 次 / 280 条（−83%）** |
| 离线可用 | ❌ 不可 | ✅ 大部分场景可 |
| 数据出域比例 | 100% | **17%** |

**这张表是本项目最硬的对比证据**：不是"我们更准"（规则本来就准），而是**在保持准确率的同时，把成本、依赖和数据暴露面都降下来了**。

对"数据不出本机"有要求的场景（党政、金融、科研未公开数据），**云端 SaaS 直接出局**，这是架构决定的结果。

## 五、答辩口径（建议原话）

> 报告数字的一致性治理已有商业方案，如 UpSlide、CCH Tagetik，但它们都面向企业，需要采购订阅、依赖 Microsoft Office、且判定过程是 AI 黑盒。
>
> 表里如一走另一条路：**不装 Office 也能运行、免费、数据全程不出本机**，用确定性计算而非模型猜测给出判断，并且**不只指出问题，还做最小改动修复并重新读取文件复核**。
>
> 我们的用户是 **学生与科研人员**——他们天然同时维护 Word 报告、Excel 数据与 PPT 汇报，数据一变就要逐篇手动改，正是这套系统要解决的问题。

## 六、需要避免的说法

| 不要这样说 | 原因 |
| --- | --- |
| 「市面上没有同类产品」 | 会被 UpSlide / CCH Tagetik 直接推翻 |
| 「我们要做国民级的」 | 无法自证，且会被追问用户量与获客方式 |
| 「小卖店也在用」 | 该类场景缺 Word 正文，与现有能力不匹配 |
| 「我们比企业产品更准」 | 没有同口径对比数据，且企业产品未公开指标 |

**主动说出竞品，并讲清架构差异，比声称"没有竞品"更可信。**
