# 知链：中文来源关联模型训练结果

## 使用口径

本轮已完成中文 BERT cross-encoder 微调，并保留字符级模型作为快速基线。Transformer 使用 `bert-base-chinese`，训练数据按文档组隔离。由于训练组和测试组规模仍较小，结果应表述为“项目内冻结测试集结果”，不能直接宣称行业泛化。

## 建议 PPT 结构

### 第 1 页：为什么要训练本地模型

标题：知链需要一个可离线运行的来源关联能力

文案：

- 规则引擎负责确定性计算与安全裁决。
- 本地 reranker 负责对“论断—事实元数据”候选进行排序。
- API 只作为困难样本的可选兜底。
- 训练目标是降低错误来源关联，同时保留人工确认机制。

配图：规则、reranker、API、人工确认四层流程图。

### 第 2 页：训练数据与防泄漏设计

标题：按文档组隔离，冻结最终测试集

数据：

| 集合 | 论断/事实对 | 文档组 | 用途 |
|---|---:|---:|---|
| train | 1,216 | 14 | 参数学习 |
| dev | 380 | 4 | 训练轮次观察 |
| final test | 340 | 7 | 最终冻结测试 |

文案：同一份长文档及其相似论断不会跨集合出现；脚本检测到文档组泄漏时会直接拒绝训练。

配图：三块数据集隔离示意图，箭头标注“group_id split”。

### 第 3 页：训练对象与输入形式

标题：模型学习五元事实元数据匹配

示例：

```text
论断：本期销售额为125万元
事实：subject=总计；metric=销售额；period=本期；unit=万元；scope=演示业务
标签：正例
```

文案：事实输入保留主体、指标、期间、单位和口径，去除事实数值；数值计算和最终裁决仍由确定性引擎完成。

配图：claim 与 fact 的双栏卡片，中间是“匹配分数”。

### 第 4 页：训练曲线

标题：中文 BERT 微调损失快速下降

放置图片：`答辩评测/中文Transformer训练曲线.svg`

讲解：3 个 epoch 内训练损失从 0.202 降至 0.016；dev 与冻结测试集均达到 100%，但样本量较小，下一步必须用新增独立文档组检验泛化。

### 第 5 页：测试结果

标题：中文 BERT 在冻结测试集上完成首轮验证

| 指标 | dev | final test |
|---|---:|---:|
| Top-1 准确率 | 100.00% | 100.00% |
| 错误关联率 | 0.00% | 0.00% |
| 论断数 | 55 | 49 |

同一 final test 上，规则基线 Top-1 为 75.51%，轻量字符基线最佳也是 75.51%；BERT 微调达到 100.00%。由于 final test 只有 7 个文档组，结论应写成“在项目冻结测试集上提升”，并明确需要新增文档组复核。

配图：规则基线与轻量训练基线的柱状图；柱顶显示 75.51%。

### 第 6 页：与现有本地 ONNX 模型的关系

标题：轻量训练基线与现成 reranker 的职责不同

文案：

- 现成 `bge-reranker-v2-m3` ONNX：用于当前产品的本地推理，已测得平均约 363ms。
- 字符级模型：快速训练基线，final test Top-1 为 75.51%。
- 中文 BERT cross-encoder：本轮微调模型，final test Top-1 为 100.00%。
- BERT v2 已导出为 ONNX，CPU batch=16 中位耗时约 182.09ms，约 11.38ms/候选对；模型权重约 409MB。

注意：不能把 BERT 微调结果写成 BGE 微调结果；现有 BGE ONNX 仍是独立的推理基线。BERT v2 ONNX 当前作为实验模型，尚未替换线上接口。

### 第 7 页：独立泛化验证揭示过拟合

标题：冻结测试集高分不等于外部泛化

放置图片：`答辩评测/中文模型迭代泛化对比.svg`

验证集为 12 个全新合成文档组、60 条论断，不参与训练，也不属于原有冻结测试集：

| 模型 | 独立合成集 Top-1 |
|---|---:|
| BERT v1 微调 | 0.00% |
| BERT v2 微调 | 100.00% |
| BERT v2 压力集 | 87.50% |
| BGE ONNX | 56.67% |

讲解：第一版 BERT 在独立组合上为 0%，扩充 48 个训练文档组后，v2 在同分布新组合达到 100%，在更换表达和字段的压力集达到 87.5%。这证明扩充训练对有效，但仍需真实中文文档组验证。

### 第 8 页：为什么暂不把 PDF 年报作为主训练集

标题：先扩事实表，再扩训练对

文案：

- PDF 需要经过文字抽取、论断切分、表格结构化、事实抽取和人工校验。
- 当前实测有效年报比例约 50%，单份产出训练对很少。
- 单位、同名指标、合并口径等问题会引入标签噪声。
- PDF 暂时保留为真实语料回归测试和产品导入测试。

配图：PDF 处理链路，并在“标注/校验”处标红耗时。

### 第 9 页：下一阶段升级路线

标题：从可复现实验走向可证明提升

1. 扩充事实表到 60～100 条，生成新的中文论断和难负样本。
2. 保持 final test 冻结，新增数据只进入 train/dev。
3. 将 v2 模型在真实中文文档组上复核，覆盖更多主体、指标、期间、单位和口径。
4. 扫描 margin/置信度阈值，比较规则、ONNX、微调模型和 API 兜底。
5. 报告 Top-1、错误关联率、误拒率、延迟和 API 调用率。

### 第 10 页：真实公开年报 PDF 外部验证（程序化标签）

标题：批量读取真实年报后，BGE 仍明显优于当前微调 BERT

数据：

| 模型 | Top-1 | 评测规模 |
|---|---:|---|
| BERT v2 | 41.32% | 36 份 PDF、576 条论断、36 个文档组 |
| BGE ONNX | 96.18% | 同上 |

文案：使用 PyMuPDF 读取 36 份公开年报文本层，自动抽取指标的本期/上期字段，并构造当前期间、上期和错误期间候选。该批次标签为程序化标签，未完成真人双人复核，因此只作为外部压力验证，不宣称为人工真值。结果再次说明 BERT v2 仍存在分布外泛化问题，BGE 保持线上默认；BERT 仅保留为后续真实中文数据扩充后的实验模型。

配图：`答辩评测/真实年报外部验证对比_36份.svg`

讲解备注：我们没有为了赶时间把程序化标签包装成人工标签，而是把 PDF 读取链路和标签来源完整记录。即使扩大到 36 份公开年报，BGE 仍达到 96.18%，BERT v2 只有 41.32%，因此线上默认模型不切换。

## 设计建议

- 主色：深蓝 `#172033`，强调色使用橙色 `#F08C46`，表示需要复核的困难样本。
- 每页只保留一个核心数字，数据页使用大号百分比。
- 训练曲线使用双图布局：上方 loss，下方 Top-1；避免把 loss 和准确率放在同一坐标轴。
- 技术架构图使用“规则 → 本地模型 → 阈值 → API → 人工确认”的横向流程。
- PDF 处理页使用灰色输入、橙色人工校验节点，表达当前不是主训练路线。

## 讲解时必须说清楚

- 本轮已完成中文 BERT Transformer 微调，同时保留字符级学习基线。
- final test 按文档组冻结，结果没有把训练数据重复用于测试。
- BERT 在当前冻结测试集达到 100%，但测试组数量较小，不能直接等同于行业泛化。
- 独立合成集上 BERT 为 0%、BGE 为 56.67%，说明当前 BERT 不能直接替换线上 BGE。
- 现成 ONNX 模型和训练模型是两个阶段：前者负责当前离线推理，后者用于后续迭代。
