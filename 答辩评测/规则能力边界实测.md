# 纯规则的能力边界（实测）

目的：回答"规则已经和多模型一样了，那模型到底干什么用"。
方法：**同一份事实表、同一批语义，只改措辞**，看规则和本地语义模型各自能不能认出来。
脚本：`答辩评测/measure_rule_boundary.py`（可复现，产物 `rule_boundary_report.json`）
口径：改写不改语义，每条改写都是同一份事实表的正确引用，gold 不变。

---

## 一、结论先行

| 系统 | 能认出候选（召回） | Top-1 正确 |
| --- | ---: | ---: |
| 纯规则 `engine.best_facts` | **38.89%** | **33.33%** |
| 本地语义模型 BGE（整张表打分） | — | **94.44%** |
| 本地语义模型 Top-2 内命中 | — | **100%** |

**在项目夹具上纯规则 100%、分层路由 100%，是因为那批文本是用事实表的词写的。**
把同一批语义换成人会写的说法，规则 Top-1 立刻掉到 22.22%（修完期间同义词后 33.33%），
而语义模型保持在 94.44%。这就是模型的岗位。

## 二、规则失败的两类原因（逐条实测）

### 类型 1：词面不一致 —— 规则要求文档必须用事实表里的**那个词**

`best_facts` 的硬门槛是 `fact['metric'] in claim_text`，指标名必须**字面出现**。

| 改写 | 规则 | 语义模型 |
| --- | --- | --- |
| 本期销售额为125万元（原句） | ✅ | ✅ |
| 本期**销售收入**为125万元 | ❌ 0 候选 | ✅ sales_current |
| 公司本期实现**营收**125万元 | ❌ 0 候选 | ✅ sales_current |
| 本期**营业总收入**达125万元 | ❌ 0 候选 | ✅ sales_current |
| 报告期内**销售金额**为125万元 | ❌ 0 候选 | ✅ sales_current |
| 本期**销售业绩**为125万元 | ❌ 0 候选 | ✅ sales_current |
| A产品**销售量**为80件 | ❌ 0 候选 | ✅ product_a |
| A产品**出货量**达80件 | ❌ 0 候选 | ✅ product_a |
| 本期**开支**为80万元 | ❌ 0 候选 | ✅ spending |
| 本期**费用**为80万元 | ❌ 0 候选 | ✅ spending |
| 本期**计划金额**为100万元 | ❌ 0 候选 | ✅ budget |

销售额 / 销售收入 / 营收 / 营业总收入 / 销售金额 / 销售业绩 —— 人一眼知道是同一个东西，
规则一条都认不出，直接 0 候选。

### 类型 2：期间写法不一致（本轮已修，属确定性可覆盖范围）

真实文档写「报告期内 / 本年度 / 去年同期」，事实表只写「本期 / 上期」。
旧实现用字面子串判断，导致上期与本期**同分并列**：

| 改写 | 修复前 | 修复后 |
| --- | --- | --- |
| 本报告期销售额为125万元 | ❌ 返回**两条**（判成口径不唯一） | ✅ sales_current |
| 报告期销售额突破120万元 | ❌ 返回两条 → 阈值拿不到唯一来源 | ✅ sales_current |

期间是**封闭词表**，属于规则该覆盖的范围，因此本轮加了 `PERIOD_SYNONYMS` 归一化
（`engine.period_in_text`），并用测试固定。规则 Top-1 由 22.22% 提升到 33.33%。

**但必须如实说明：这次修复对真实年报识别率没有帮助**，见下节。

## 三、真实语料：规则识别率 0.5%（3/580）

同一份真实年报（169 页、第 10—45 页、40,008 字、580 个含数字句子）：

```
引擎识别出论断的句子: 3 / 580 = 0.5%     ← 加期间同义词后仍是 3/580
```

未识别的样例与原因：

| 真实年报原文 | 规则为什么做不到 |
| --- | --- |
| `公司…营业收入占比已超过公司全部营业收入的50%以上` | 算子与数值之间隔着长定语，句式不规则 |
| `公司产品长链二元酸产量增加179.79%，销量增加432.69%` | 裸「增加」没有期间限定词 |
| `生物基、淀粉基新材 增加187.44` | **表格残片**：科目名被 PDF 截断，且无单位 |
| `化学原料及化学制 减少11.78` | 同上 |

结论：真实语料的瓶颈**不只是词表**，还有句式与 PDF 抽取本身。所以：

- 想靠"再加几组正则"解决真实语料是不现实的；
- 但也不能把这件事全推给模型——**表格残片类（科目被截断、无单位）连模型也判不了**，
  这类必须靠 **PDF 表格结构化**（`pdfplumber.extract_tables()`，已验证结构规整）。

## 四、规则反而更强的地方（防止被反问"那模型为什么不干脆全接管"）

| 能力 | 谁做 | 实测 |
| --- | --- | --- |
| 数值计算、单位换算、千分位 | 规则 | 只认 20 条真实写法，`Decimal` 精确 |
| 增长率方向（增加/减少/上升） | 规则 | 「减少」反号曾静默出错，已修并加测试 |
| 排名需要完整比较集合 | 规则 | 缺可比对象时 `unverifiable / source_conflict` |
| 阈值与预算两侧口径 | 规则 | 期间+指标都要显式出现，否则宁可留空 |
| 文件写回与版本事务 | 规则 | 模型永不写文件 |
| **词面之外的语义召回** | **模型** | 本页 94.44% vs 33.33% |

模型也不是稳赢：`报告期销售额突破120万元` 这条，BGE 选了 `sales_prev`（raw −3.09，
低于校准阈值 −3.0），生产环境会**弃答转人工**。所以语义模型的作用是"把候选召回出来"，
最终裁决仍在确定性引擎与人工闸门。

## 五、答辩口径（建议原话）

**问"规则和分层路由指标一样，模型是不是多余的？"**

> 在项目夹具上确实一样，因为那批文本就是按事实表的词写的。我们把同一批语义只改措辞
> 重测了一遍：规则 Top-1 从 100% 掉到 33%，本地语义模型是 94%——比如"销售额"写成
> "销售收入""营收""营业总收入"，人一眼知道是同一个东西，规则一条都认不出。
> 所以两者不是替代关系：规则负责词面能对上的部分，模型负责词面对不上的部分。

**问"真实文档上到底行不行？"**

> 不行，这是我们主动公开的最大短板：169 页真实年报里 580 个含数字句子，规则只认出 3 句，
> 0.5%。而且瓶颈不只是词表——里面有 `生物基、淀粉基新材 增加187.44` 这种表格残片，
> 科目名被 PDF 截断又没单位，模型也判不了。所以我们下一步不是"再加正则"，
> 而是把 PDF 财务表结构化，让事实表先对得上。

**问"那为什么不干脆全用模型？"**

> 因为数值计算、单位换算、增长率方向、排名的比较集合这些，规则是 100% 且可审计的；
> 模型只在词面对不上时出场，而且它的建议绝不直接写进文件、必须过人工闸门。
