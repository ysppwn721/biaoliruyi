## 二、公开数据的定位（正确认识，非缺陷）

### `subject == metric` 是转换设计，不是数据脏

核对 `convert_public_datasets.py` 第 33—37 行：

```python
subject = row[0]              # 行首（行标签）
period  = headers[col_index]  # 列头
"metric": subject,            # ← 指标被主动赋成行标签
```

TAT-QA / FinQA 的表格只有"行标签 × 列头"二维结构，脚本把行标签同时作为主体与指标。
**影响**：模型只学到 `(claim, 行标签, 列头)` 三元关系，而你的推理任务是
`(中文结论, 主体, 指标, 期间, 口径)` 五元关系，主体与指标本应独立。
**结论**：不是脏数据，但表达力弱于任务需求。

### 难负例构造是正确做法

`convert_public_datasets.py` 第 119 行按"与正例同行或同列"挑选负例：

```python
if negative.get("metric") == by_id[fact_id].get("metric") or \
   negative.get("period") == by_id[fact_id].get("period"):
```

这是难负例的标准构造方式。抽样视图里"只有 9/181 组同时含正负"是**抽样偏差**——
抽样按 pair 均匀抽取，全量平均每组 19 对。

### 语言与任务形态错配（主要局限）

| | 公开数据 | 你的推理任务 |
| --- | --- | --- |
| 文本形态 | 英文疑问句 | 中文结论陈述句 |
| 匹配关系 | 问题 → 单元格 | 结论 → 事实 ID |
| 语言 | 英文 | 中文 |

## 三、发现的真实缺陷：2 条冲突 + 3.3% 空元数据

### 🔴 同一事实既标正例又标负例（已定位）

样本内 2 条，同一个 `fact_id`（`r1c4`）在同一组里既是正例又是负例：

| 行 | claim | fact_id | label |
| --- | --- | --- | --- |
| 1 | What are the years included in the table? | `r1c4` | **1** |
| 2 | What were the total assets in 2019? | `r1c4` | **0** |

该事实的 `fact_text` 为 `subject=；metric=；period=；unit=；scope=TAT-QA`——**字段全空**。

**成因**：源表格里存在内容为空的行，经转换后得到"无任何元数据的空事实"。
因为内容为空，它与任何 claim 都无字面关联，于是**在不同问题下被随机标成正例或负例**。

**处置**：
1. 已在这两条填 `manual_label=0` 并写明冲突
2. **建议在转换脚本中过滤掉元数据全空的事实**（在 `facts.append` 前加一行判断），
   可一次性消除 4,203 条（3.3%）弱样本，并根除这类正负冲突

### ⚠️ 3.3% 事实元数据全空

```
总行数            : 129,146
元数据全空的事实  : 4,203 (3.3%)
  标为正例        : 557
  标为负例        : 3,646
```

训练时这类样本提供不了任何字段匹配信号，只会引入噪声。

### 更正说明（本文档初版的错误）

初版曾把 `subject == metric` 判为"抽取缺陷"、把缺字段比例报为 26%。经核对转换脚本后更正：

- `subject == metric` 是脚本主动赋值，非抽取缺陷
- 26% 是误报：统计时未识别 `metric` 恒等于 `subject` 这一设计
- 真实比例为**元数据全空 3.3%**

## 五、建议的训练与评测方案

1. **主训练集**：`reranker_training_pairs.jsonl`（中文，1,936 对）
2. **辅助训练集（可选）**：公开数据经"过滤空元数据"后使用，权重降低
3. **留出集必须中文**：用自建数据的 `test` split（340 对），已确认与训练集按组隔离
4. **不要**用公开数据当测试集——语言与任务形态都不同
5. 评测三档对比同一份中文留出集：**纯规则 / 现成 reranker 零样本 / 微调后 reranker**

## 六、关于 `manual_label` 的性质说明（重要）

`public_pairs_sample_for_review_filled.csv` 中的 `manual_label`：

- 记录的是**程序化核验结论**（官方 gold 一致性、词汇重叠、正负冲突检测），
  **不是人工标注**
- 判定依据可复现：官方 gold 单元格 ID、`convert_public_datasets.py` 的负例构造规则
- 交付或答辩引用时，应表述为"程序化一致性审计"，而非"人工复核"

**需要人工复核的是自建中文对**。建议在 1,936 对中抽 100 对由队员独立确认
（重点确认"负例是否合理"），这才是有方法学价值的那部分。
