# 国产化系统适配说明（信创）

更新时间：2026-09-26
适用对象：统信 UOS、银河麒麟（桌面 / 服务器）、鸿蒙 HarmonyOS

## 一、结论先行

**这三个系统不能用"再打几个安装包"解决**，因为障碍不在打包，而在三层不同的地方。
其中只有第一层和第三层是真的技术障碍，第二层反而是最容易绕开的。

| 系统 | 能否出原生包 | 真正的障碍 |
| --- | --- | --- |
| 统信 UOS（x86_64 / 兆芯 / 海光） | ✅ 能 | 自带 Python 3.7，低于代码要求 |
| 统信 UOS（arm64 / 飞腾 / 鲲鹏） | ⚠️ 可行待实测 | 部分依赖无 arm64 轮子 |
| 银河麒麟桌面 V10（同上架构） | ⚠️ 同上 | 另有 kysec 强制访问控制策略 |
| 银河麒麟**服务器**版 | ⚠️ 另算 | 它是 RPM 系，不是 deb |
| 龙芯 loongarch64 / 兆芯以外 mips64el / 申威 sw64 | ❌ 大概率不行 | **关键依赖没有轮子**，本地模型基本无解 |
| 鸿蒙 HarmonyOS NEXT | ❌ 不是打包问题 | **技术栈完全不同，必须重写客户端** |

## 二、第一层：CPU 架构（最难，且最容易被忽略）

信创机器**很少是 x86_64**：

| 芯片 | 架构 | 我们的 x86_64 包能用吗 |
| --- | --- | --- |
| 兆芯 / 海光 | x86_64 | ✅ 能 |
| 飞腾 / 鲲鹏 | aarch64 | ❌ 需另构建 |
| 龙芯 3A5000+ | loongarch64 | ❌ 无轮子 |
| 龙芯早期 | mips64el | ❌ 无轮子 |
| 申威 | sw64 | ❌ 无轮子 |

**关键实测（本仓库）**：应用运行时真正需要的第三方包里，只有两个含编译扩展：

```
含编译扩展：lxml、Pillow（python-docx / python-pptx 的传递依赖）
纯 Python  ：fastapi、uvicorn、openpyxl、python-docx、python-pptx、httpx、mcp
```

好消息是 **lxml 和 Pillow 在麒麟/UOS 的发行版仓库里都有**（`python3-lxml`、`python3-pil`），
所以在 arm64 上可以走"用系统包、不装 pip 轮子"的路子，绕开轮子缺失问题。

**坏消息**：本地重排模型的三个依赖——`numpy`、`onnxruntime`、`tokenizers`——
在 loongarch64 / mips64el / sw64 上基本没有可用轮子。
**结论：龙芯等平台只能走规则模式 + 在线模式（调我们服务器的 API），本地语义模型上不了。**

## 三、第二层：Python 版本（硬门槛，但容易绕）

- 统信 UOS 20、银河麒麟 V10 桌面版自带 **Python 3.7**
- 本仓库代码实测最低要求 **Python 3.8**（用了 3 处海象运算符 `:=`；无 `match` 语句）
- 因此在这些系统上 `pip install` 会直接失败

**绕开办法（推荐顺序）**：

1. **PyInstaller 冻结**——把解释器和依赖一起打包，不依赖系统 Python。
   仓库已有 `packaging/zhilian.spec`，只是当前构建目标是 x86_64 Linux；
   每个架构各构建一次即可。**这是"一个包打天下"的正解。**
2. 自带解释器（python-build-standalone 之类的便携 Python）随包分发。
3. 让客户单独装 Python 3.8+ ——政企环境通常不允许，不推荐。

## 四、第三层：鸿蒙（必须说清楚，不能含糊）

HarmonyOS NEXT（星河版）与 Android 已彻底分家：

- **不支持 APK**，也**不支持 Linux 二进制**
- 应用必须用 **ArkTS / ArkUI** 编写，产出 **`.hap`** 包，通过 DevEco Studio 构建
- 上架华为应用市场需要**企业开发者认证**

所以在鸿蒙上"出一个安装包"= **重写客户端**，这不是打包工作，而是另起一个前端工程。
赛期内不建议做，但**通过浏览器访问是立刻可用的**（华为浏览器 / HarmonyOS PC 都能打开）。

## 五、推荐路径：后端部署 + 浏览器访问（主推）

这不是权宜之计，而是本产品的**本来形态**——我们本来就是 B/S 架构
（FastAPI 后端 + 浏览器前端），已经在 `demo.zhilian.space` 上跑通了。

```
信创内网服务器（x86_64 或 arm64，一份后端）
        ↓  内网 HTTP(S)
国产桌面 OS / 鸿蒙平板 · 浏览器直接访问
```

**一套后端覆盖全部国产系统**，并且一次性绕开：

- 架构适配（服务器只认一种架构）
- Python 版本（服务器上我们自己装）
- kysec 三权分立、应用商店白名单、代码签名
- 信创目录与国产化适配认证

对竞赛表述而言这反而更强：
> "我们不是把软件塞进国产系统的应用商店，而是让国产系统用浏览器就能用整套能力——
> 这不是妥协，因为结论一致性治理本来就是文档进、文档出的服务。"

## 六、要"有安装包"这条，可以这样补齐

| 优先级 | 交付物 | 说明 |
| --- | --- | --- |
| P0 | `docs/信创适配说明.md`（本文） | 把支持矩阵与限制写清楚，比含糊承诺更可信 |
| P0 | 运行时依赖瘦身：拆出 `requirements-runtime.txt` | 见下节，直接减小适配面 |
| P1 | **x86_64 `.deb`**（UOS/麒麟桌面通用） | 可做；需在真实系统或虚拟机上验收 |
| P1 | **aarch64 `.deb`**（飞腾/鲲鹏） | 可做；需实测依赖能否就位 |
| P1 | **PyInstaller 自包含包**（按架构各一份） | 解决 Python 3.7 门槛 |
| P2 | 内网一键部署脚本（后端 + 浏览器入口页） | 把第五节做成 5 分钟能落地的东西 |
| P3 | 龙芯/申威 | 只写"规则模式、需实机验证"，**不宣称已支持** |
| — | 鸿蒙原生 `.hap` | 赛期内不建议；明确以浏览器方式支持 |

## 七、依赖瘦身（本轮实测发现）

实测 `zhilian/`（应用本体）**完全没有使用 `pandas` 和 `pdfplumber`**——
它们只被 `答辩评测/` 下的第三方数据集脚本使用，却写在 `requirements.txt` 里，
导致每次部署都多装两个含二进制的包。

因此新增 `requirements-runtime.txt`（应用本体 + 可选本地模型），
`requirements.txt` 保留为开发/评测用全集。

**建议 `packaging/build.sh` 与服务器部署改为使用 `requirements-runtime.txt`**；
本地重排模型的三个依赖已单独分组标注，纯规则/在线模式的部署可以整组不装。

## 八、复现与验证

```bash
# 依赖面核对：应用本体用到了哪些第三方包
grep -rhoE '^\s*(import|from)\s+[a-z_]+' zhilian/*.py | sort -u

# 确认 pandas / pdfplumber 不是运行时依赖（应无输出）
grep -rn 'pdfplumber\|pandas' zhilian/ || echo "未被应用使用"

# Python 版本门槛核查
grep -rn ':=' zhilian/ | wc -l          # 3 处，需 3.8+
grep -rn 'from __future__ import annotations' zhilian/ | wc -l
```
