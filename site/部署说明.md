## 二、现在怎样演示（本机）

```powershell
# 1. 启动服务（监听全部网卡，供隧道转发）
$env:ZHILIAN_HOST='0.0.0.0'
$env:ZHILIAN_PORT='8765'
$env:ZHILIAN_ACCESS_PASSWORD='zhilian2026'
.\.venv\Scripts\python.exe run.py

# 2. 另开一个窗口，建隧道（地址会打印在输出里）
& 'C:\Program Files (x86)\cloudflared\cloudflared.exe' tunnel --url http://127.0.0.1:8765 --no-autoupdate
```

本机验证：

```powershell
Invoke-RestMethod http://127.0.0.1:8765/api/health          # 应返回 401（有密码保护）
curl.exe -u zhilian:zhilian2026 http://127.0.0.1:8765/api/health   # 应返回 status: ok
```

## 三、为什么保留密码保护

大赛要求「软件若设置了用户名和密码，必须在显著位置注明测试账号和密码」。
保留保护的价值：

1. **不被爬虫和陌生人误用**——演示环境开放写入（可创建项目、下载文件），无保护会有被滥用的风险；
2. **符合大赛要求**——账号已在站点和设计文档中公开；
3. **演示可复现**——评委用同一账号进入，看到一致的环境。

如需对外完全开放（不推荐），把 `ZHILIAN_ACCESS_PASSWORD` 置空即可，改动只有一行配置。

## 四、部署下载页到 Cloudflare Pages

站点文件在仓库 `site/` 目录。

### 方式 A：连接 GitHub（推荐，push 即自动部署）

1. Cloudflare 控制台 → Workers & Pages → Create → Pages → Connect to Git
2. 选择本仓库，授权
3. 构建设置：
   - Framework preset：`None`
   - Build command：**留空**
   - Build output directory：`site`
4. 保存并部署，得到 `xxx.pages.dev` 地址
5. 绑定自有域名：Pages → Custom domains → 添加你的域名

### 方式 B：直接上传（不接 GitHub）

```powershell
npx wrangler pages deploy site --project-name biaoliruyi
```

当前项目已经创建并部署到 `https://biaoliruyi.pages.dev/`。若要让 `zhilian.space` 显示同一站点，在 Cloudflare DNS 添加 CNAME：主机名 `@`，目标 `biaoliruyi.pages.dev`；如已有旧的 A/CNAME 或 Worker 路由，需要先移除冲突记录。Pages 自定义域名状态变为 Active 后，下载链接会在 `https://zhilian.space/` 生效。

首次运行会要求登录 Cloudflare（浏览器授权）。

## 五、升级为自有域名（决赛前必做）

Quick Tunnel 地址会变、无可用性保证，决赛前应换成**命名隧道 + 自有域名**：

```powershell
# 1. 登录（浏览器授权，会写入 ~/.cloudflared/cert.pem）
cloudflared tunnel login

# 2. 创建命名隧道
cloudflared tunnel create biaoliruyi

# 3. 绑定域名（把 demo.你的域名 指向该隧道）
cloudflared tunnel route dns biaoliruyi demo.你的域名

# 4. 写配置 ~/.cloudflared/config.yml
#    tunnel: <上一步返回的隧道ID>
#    credentials-file: C:\Users\<你>\.cloudflared\<隧道ID>.json
#    ingress:
#      - hostname: demo.你的域名
#        service: http://127.0.0.1:8765
#      - service: http_status:404

# 5. 运行
cloudflared tunnel run biaoliruyi
```

**关于备案**：域名在大陆注册商注册**不等于**必须备案。
只有把域名解析到**大陆境内主机**时才必须完成 ICP 备案（约 1–3 周）；
解析到 **Cloudflare / 境外主机不需要备案**。本方案属于后者。

**稳定性建议**：本机需保持开机与联网。若要长时间稳定，
把 `Dockerfile` 部署到境外云主机，再用命名隧道指向该主机：

```bash
docker build -t biaoliruyi .
docker run -d --name biaoliruyi -p 8765:8765 \
  -e ZHILIAN_ACCESS_PASSWORD=zhilian2026 \
  -e ZHILIAN_HOST=0.0.0.0 \
  -v biaoliruyi-data:/data \
  --restart unless-stopped biaoliruyi
```

## 七、已注意到的风险

1. **Quick Tunnel 地址会变**：进程重启即换新地址。若已把旧地址写进文档或视频，需要同步更新。
2. **本机依赖性**：笔记本休眠、断网都会导致演示环境不可用。决赛前务必换成云主机常驻。
3. **数据为临时数据**：`.zhilian/` 是运行时目录，容器重启后数据丢失。
   正式演示前建议预先创建好演示项目，避免现场首次生成。
4. **模型不随包分发**：543MB 的 ONNX reranker 未进入仓库（GitHub 单文件限 100MB），
   也不进安装包。演示机需提前放置模型，否则自动降级为规则模式——
   这也正是三档设计要保证的能力。
