## 二、云服务器部署

按照 [deploy/README.md](../deploy/README.md) 将部署文件上传至阿里云服务器。安全组放行 TCP 80/443，DNS A 记录指向服务器公网 IP，然后执行 `docker compose up -d --build`。

验证：`curl -u zhilian:<部署密码> https://zhilian.space/api/health` 应返回 `status: ok`；浏览器打开 `https://zhilian.space/demo/` 即进入真实工作台。

## 三、为什么保留密码保护

大赛要求「软件若设置了用户名和密码，必须在显著位置注明测试账号和密码」。
保留保护的价值：

1. **不被爬虫和陌生人误用**——演示环境开放写入（可创建项目、下载文件），无保护会有被滥用的风险；
2. **符合大赛要求**——账号已在站点和设计文档中公开；
3. **演示可复现**——评委用同一账号进入，看到一致的环境。

如需对外完全开放（不推荐），把 `ZHILIAN_ACCESS_PASSWORD` 置空即可，改动只有一行配置。

## 四、部署下载页到 Cloudflare Pages

站点文件在仓库 `site/` 目录。

### 方式 A：连接 GitHub（推荐，push 即自动部署）

1. Cloudflare 控制台 → Workers & Pages → Create → Pages → Connect to Git
2. 选择本仓库，授权
3. 构建设置：
   - Framework preset：`None`
   - Build command：**留空**
   - Build output directory：`site`
4. 保存并部署，得到 `xxx.pages.dev` 地址
5. 绑定自有域名：Pages → Custom domains → 添加你的域名

### 方式 B：直接上传（不接 GitHub）

```powershell
npx wrangler pages deploy site --project-name biaoliruyi
```

当前项目已经创建并部署到 `https://biaoliruyi.pages.dev/`。若要让 `zhilian.space` 显示同一站点，在 Cloudflare DNS 添加 CNAME：主机名 `@`，目标 `biaoliruyi.pages.dev`；如已有旧的 A/CNAME 或 Worker 路由，需要先移除冲突记录。Pages 自定义域名状态变为 Active 后，下载链接会在 `https://zhilian.space/` 生效。

首次运行会要求登录 Cloudflare（浏览器授权）。

## 五、域名和 HTTPS

将 `zhilian.space` 的 A 记录指向阿里云服务器公网 IP。若 DNS 由 Cloudflare 托管，可以开启代理；Caddy 会自动申请并续期 HTTPS 证书。无需 Quick Tunnel，也无需额外的 `demo.` 子域名。

用户数据保存在 Docker volume 中，容器设置为 `restart: unless-stopped`，服务器重启后会自动恢复。

## 七、已注意到的风险

1. **服务器安全组**：必须放行 TCP 80 和 443，应用容器端口 8765 不需要对公网开放。
2. **数据持久化**：不要删除 Docker volume；正式演示前建议预先创建好演示项目。
3. **模型不随包分发**：543MB 的 ONNX reranker 未进入仓库（GitHub 单文件限 100MB），
   也不进安装包。演示机需提前放置模型，否则自动降级为规则模式——
   这也正是三档设计要保证的能力。
