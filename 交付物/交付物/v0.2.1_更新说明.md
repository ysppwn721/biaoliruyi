## 一、修复的真实缺陷

### 🔴 P0：事实表导入的 O(行数²) 性能缺陷

`office.read_facts` 在 `load_workbook(read_only=True)` 下每行调用 `sheet.cell()`，
而该模式下每次 `cell()` 都要重新解析工作表 XML，整体是平方级复杂度。

**本机实测（合成长表）：**

| 行数 | 修复前 | 修复后 |
| --- | --- | --- |
| 200 | 1.035s | 0.015s |
| 500 | 8.649s | 0.029s |
| 1000 | 54.664s | 0.057s |
| **1999（产品上限）** | **173.360s** | **0.128s** |

产品宣称支持 2000 行，但真实用户导入 500 行就会以为程序卡死（前端只有"正在解析"
遮罩、无进度）。修复方式：列字母在循环外算一次，坐标改为
`get_column_letter(列) + 行号`，**输出坐标与原实现逐字节一致**（E2…E2000）。

### 🟠 P1：Word 页眉页脚漏发"未纳入检查"警告

原判断只检查 `s.header.paragraphs[0]`。构造"第一段空、第二段有字"的页眉时
**不产生任何警告**，用户会误以为页眉已被核验。现改为逐段检查，并覆盖页眉表格
（页眉里的表格同样不在自动检查范围内）。

### 🟠 P1：MCP 依赖锁死导致换机即崩

`requirements.txt` 锁 `mcp==1.30.0`，而 `mcp` 2.x 把 `FastMCP` 改名为 `MCPServer`。
在装了 2.x 的环境里 `import mcp.server.fastmcp` 直接 ModuleNotFoundError，
`test_tools.py` 无法收集。现 `mcp_server.py` 对 1.x / 2.x 双兼容
（两者的 `add_tool` / `run` / 构造签名一致，仅导入路径不同），
依赖声明放宽为 `mcp>=1.30,<3`。

### 🟡 P2：核验错误分类与提示文案耦合

`engine.check` 原先靠比对 `reason` 字符串常量来判定错误分类
（`missing_data` / `source_count` / `scope_mismatch` 等）。任何一处提示文案被润色
（例如"请"改"您"）都会让分类**静默退化**为 `needs_review`，进而影响诊断分组与
报告分组。现改为结构化错误码：新增 `CheckError(code, message)`，15 处 raise 全部
改为带码抛出，分类不再与文案耦合。

> 分类口径保持与旧实现一致：少了来源→`missing_data`，多给了来源→`source_count`，
> 引用指向不存在的事实→`missing_data`。144 项既有测试可证明行为未变。

## 二、补回缺失的核心能力：事实依赖图

**这是交付包此前完全没有的机制。** 原先论断与事实之间只有扁平引用
（`claims.refs`），事实之间没有依赖关系，因此：

- 「利润 = 销售额 − 成本」这类推导无法表达；
- 改一个基础事实后，"哪些结论是**推导出来的**、会连带失效"只能靠人工判断。

新增 `zhilian/graph.py`（团队原创，纯标准库实现）：

| 能力 | 说明 |
| --- | --- |
| 派生事实 | 4 种受限表达式：`sum` 合计、`diff` 差额、`ratio` 比率、`growth` 增长率 |
| 拓扑排序 | 保证任何派生事实都排在其来源之后 |
| 环依赖检测 | 循环定义直接报错，不会静默算出一个数 |
| 传递闭包 | 从变化的事实出发，找出全部间接受影响的派生事实 |
| 级联重算 | 基础事实变化后按拓扑序自动重算下游 |
| 影响半径 | 受影响节点 ÷ 全图节点 |
| 影响分组 | 区分**直接受影响**与**经依赖图传播后才受影响**的论断 |

**接入方式**：派生事实并入 `ws['facts']`，因此论断与图表都能引用它们；
`change` 与 `import_sources` 的响应新增 `cascade` 字段。

**安全边界**（与既有"确定性优先"原则一致）：
- 派生事实**不写回 Excel**，只存在于工作区；
- **不能直接修改**派生事实的数值（它由表达式决定）；
- 非法定义（引用不存在、自引用、重复 ID、循环依赖、非白名单运算）**拒绝写入且不落盘**；
- 被其他派生事实引用的定义**不允许删除**。

### 顺带修复的两个约束缺陷

这两个是补依赖图时暴露出来的，原本会**静默算错**：

1. **差额要求指标一致** → 导致"销售额 − 成本"这种合法计算无法表达。
   现只要求主体与口径一致，允许指标不同。
2. **合计要求主体相同** → 与"多项求和"语义相反。现要求指标、期间、口径一致、
   主体允许不同（A产品 + B产品），并对**重复主体报错**以防重复计数。

## 三、事实定位引擎加速（等价改写）

`best_facts` 原先对每段文本遍历全部事实做子串包含判断。现改为先按
"描述符 → 事实 ID" 反向索引缩小候选，再对候选做与旧实现**完全相同**的判断。

**实测（合成长文档，3610 事实 / 2000 段）：**

| 规模 | 优化前 | 优化后 |
| --- | --- | --- |
| 1200 事实 / 2000 段 | 0.93s | 0.43s |
| 3610 事实 / 2000 段 | 3.48s | 0.68s |

**语义等价性用 45 组新旧对照验证，分歧数为 0。**

> 期间只参与加分、不参与"能否匹配"。开发中曾误把期间列为必需描述符，
> 导致「A产品销量最高」这类没写期间的句子**匹配不到任何事实**，
> 已修正并由测试锁定。
